# Bypass text check for recognized slash commands

Type: task
Status: resolved
Blocked by: (none)
Assignee: pi (2026-08-23)

## Question

Bypass the player-input text check for recognized steering slash commands (`/guide`, `/narrator`, `/impersonate`) in `action_check_handler`, because steering text is an instruction to the model, not player dialogue. Unknown slash and plain input keep the check as today.

## Context

Resolved by grilling ticket 14 (Q7, decision A). The text check exists to catch errors in player-typed prose before it enters history. Steering text is not player prose:

- `/guide` — not persisted; a one-shot instruction to the model.
- `/narrator` — a directive persisted as a Narrator row, not dialogue.
- `/impersonate` — output is generated by the model, not typed.

Checking the raw command (slash prefix included) as if it were dialogue clutters the confirm flow with irrelevant flags on imperatives and fragments.

## Scope

1. **`src/adapters/driving/http/action/handlers/actions.rs::action_check_handler`** — before calling `text_check_service.check_player_input`, detect a recognized `Action::parse(&command)` variant. If the command parses to `Guide`/`Narrator`/`Impersonate`, dispatch directly (`dispatch_action`) and return, skipping the check. If it parses to `FreeAction` (unknown slash or plain input), run the existing check path unchanged.
2. **Do not** check the argument-only variant (Q7 chose A, not B). The bypass is all-or-nothing per recognized command.
3. **Test** — add an HTTP test asserting that a recognized slash command with intentionally flagged words does **not** surface a text-check preview, while a plain `FreeAction` with the same words does. Tag against the existing `docs/specs/actions.md` scenarios (1.9–1.11) or add a small scenario if a dedicated assertion is cleaner — the grilling decided no new `steering.md`, so prefer reusing existing scenarios or an invariant.
4. **Unit alternative** — if an HTTP test is awkward to frame (the check runs before dispatch), a unit test on a small extracted helper is acceptable. Prefer the tier that tests the actual branch.

## Notes

- Re-verify the current `action_check_handler` shape before editing; it calls `check_player_input(&command, mode, ignored_words)` then either renders a `TextCheckPreviewTemplate` or dispatches.
- `Action::parse` is case-insensitive on the leading slash (`/guide`/`/narrator`/`/impersonate`); unknown slash and bare input fall through to `FreeAction`.
- This is the last open behavior gap on the steering surface. The `GenerationReplay`→`SteeringRecord` rename remains a separate deferred mechanical ticket, not a gate.

## Resolution

Implemented and build-green.

### What changed

- `src/domain/model/action.rs` — added `Action::is_steering()` (classifies `Guide`/`Narrator`/`Impersonate` as steering) so the variant set lives on the enum, not at each match site.
- `src/adapters/driving/http/action/handlers/actions.rs` — extracted `dispatch_with_status_headers(state, command)` (the `dispatch_action` + `add_status_swap_headers` + return shape), collapsing four copies (the new steering bypass plus the three pre-existing disabled/auto-check-off, check-error, and clean-`None` arms). `action_check_handler` now calls `Action::parse(&command).is_steering()` before consulting settings: recognized steering dispatches directly under any settings (steering text is a model instruction, not player prose); `FreeAction` (unknown slash, plain input, empty) keeps the check path unchanged. All-or-nothing per command (Q7 decision A): the argument is never checked in isolation.
- `src/domain/model/action_tests.rs` — two unit tests for `is_steering` (true for the three steering variants incl. `Impersonate(None)`; false for `FreeAction` incl. the unknown-slash fallback).
- `docs/specs/actions.md` — new Scenario 1.12 (Slash commands section): recognized steering command with a deliberate misspelling (`/guide look at the casle`) surfaces no text-check preview and dispatches directly; the same words as plain input surface the preview.
- `tests/http/actions.rs` — `test_slash_command_bypasses_text_check_http` tagged `SCENARIO: 1.12`: Spell mode + auto-check enabled, real Harper checker; asserts the `/guide` command sets `HX-Retarget` (dispatch) with no `text-check-preview` in the body (and the guide generation completes), then asserts plain `look at the casle` has no `HX-Retarget` and returns the `text-check-preview` fragment. HTTP tier chosen over the unit-helper alternative because it tests the actual branch through the real driving adapter.
- `tests/http/test_helpers.rs` — added `post_action_check` (POST form body to `/action/check`) and `app_with_narrator_and_settings` (narrator backend + explicit `AppSettings`; `app_with_narrator` now delegates with defaults).

### Validation

- `python build.py` green (all 12 steps; 1462 tests passed, 2 LLM tests skipped). One pre-existing suite flake (`architecture::arch_lint_check`) passed on nextest retry and in isolation; unrelated to this change.
- `scripts/validate_feature_spec.py`: 109 declared, 109 covered, 0 gaps, 0 orphans. Its exit-1 duplicate-ID report (17.1–17.3 in `browser.md` vs `games.md`) pre-exists this change (verified on HEAD) and is not a `build.py` gate.

### Review-driven follow-up

A two-axis code review surfaced three findings; all three were applied before closing:
- `Action::is_steering()` method replaces the handler-local `is_steering_command` predicate (classification now lives on the enum).
- `dispatch_with_status_headers` extraction collapses the four duplicated `dispatch_action` + `add_status_swap_headers` + return blocks (the steering bypass plus three pre-existing arms).
- The dispatch assertion was tightened from a loose `contains("status")` body substring to the `HX-Retarget` header (present on dispatch, absent on preview), matching the existing `test_action_check_no_issues` convention.

| OR-51 | 2026-10-12 | R-81 and OR-31: what a stop undoes | A stop drops only the generation or the Options run that runs when the stop arrives. Every Message and Swipe that the work saved before stays. A stop during the Narration of a free-text Action keeps the Input. A stop during an event Narration keeps the Narration that fired the Trigger. Its trigger context stays, so the story log offers Retrigger on it, and the status shows no failure. A stop during the Options run after a Narration leaves no offered set. A stop during an `/options` run leaves the offered set as it was. This replaces the undo part and the examples of OR-31. | Owner: "Pushing a [STOP] doesn't delete the input because the generation and the input are two separate operations." Then Option A of ticket 22, round 2, Q2 ("only the generation that runs now"). Rejected: undo every generation of the request but keep the Input (Option B), and undo the whole request (Option C, OR-31 as written). The example in OR-31, "a stopped free-text Action leaves no Input", came from the grilling's wording, not from the owner's words. |
| OR-52 | 2026-10-12 | OR-48 | Withdrawn. After a stop, the Input stays in the story, so the dashboard does not put the player's text back in the input box. | Follows from OR-51. |
| OR-53 | 2026-10-12 | When the story shows a generated text, and what a stop during the analysis keeps (new R-11a; R-81) | The story log shows a generated text as soon as the narrator call returns. This narrows OR-51: the step that a stop drops is a narrator call, an analysis or an Options run. | Owner: "Having to wait until the quantifier runs to show the message would take too long. The grilling applies the rule to every analysed generation: a Narration, an Impersonate Input and an event Narration. |

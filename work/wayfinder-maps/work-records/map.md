# Map: Work records

Labels: wayfinder:map
Status: open

## Destination

The work records of this repo live in one visible folder: the maps, the one-off items, the plans, and the memory of the work. Research on how others do this chose its names and layout. Maps sit side by side, one-off issues sit in status folders, and one wiki holds the memory of all work. Several chief-of-staff sessions can share that wiki, each with its own goal, and need no folder of their own. The records are moved, the docs and skills are updated, and the link check and the gate pass. After a period of use, the owner keeps the layout or changes it.

- **The needs (owner, charting).** Each research ticket and the review after use check each approach against this list. The layout must make these easy:
  1. See each goal and where it stands, without asking an agent.
  2. Put a one-off item in one obvious place.
  3. Keep the rules that span maps in one place, not copied into each map's Notes.
  4. Let a chief find its goal and its memory in the one wiki, and its records from the tracker doc. (Rewritten on 2026-11-11 by [Decide what a workstream is for, or drop it](issues/11-workstream-purpose.md). It said: "Let a chief own one folder and find everything it needs from there.")
  5. Close a goal as one unit.
  6. Let a fresh agent find any record from one doc (the tracker doc).
- **Working views (owner, 2026-11-04).** The research and grilling tickets test these views, and can overturn them:
  - The top folder is visible, with no dot.
  - The names are decided (tickets 04 and 11): the top folder is `work/`, and a one-off is an **issue** with no map. **Map** and **ticket** keep their wayfinder meanings. A ticket is a child issue of its map. There are no workstreams.

  - The names describe the workflow, so they go in `docs/agents/`, not in `CONTEXT.md` (the game glossary).
- **Scope (owner, charting).** `.scratch/` and `docs/plans/`, in this repo. A layout that also fits other repos is a plus, but it is not required.

## Decisions so far

<!-- the index — one line per closed ticket: enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [Find how Claude Projects and similar tools organize work and memory](issues/01-claude-projects.md) — "Project" means three things. Only the Claude Code project (public beta) is close to an expedition: a goal, instructions, memory files, a Library and threads, with a state view (Waiting on you … Resolved). The user writes instructions, the model writes memory. Claude Code memory is current-state: a short index (200 lines or 25KB) and topic files on demand. Work outside a project has no named place. The docs fit a project to "an area you keep feeding", which may make the bucket maps expeditions (inferred).
- [Find how Pocock's chief of staff and the LLM wiki keep memory](issues/02-chief-of-staff-wiki.md) — Karpathy's "LLM Wiki" gist (2026-04-04) is the origin, and its wiki is "kept current". "Write history, not the present" is Pocock's own rule (`5beb35b`), and no script checks it. The skill defines no goal folders. Pocock's posts show one wiki per person, per deliverable or per domain agent. Nothing is merged upstream after `4ae2317`, but draft PR #1369 says chief-of-staff "may replace wayfinder" and moves a map's destination and fog into a `destination.md` wiki page. Fits need 3, part of 1, 4 and 6, not 2 or 5. The report's "broken procedure paths" was wrong: they resolve after install (PR #1363).
- [Find how other tools and people lay out agent work in a repo](issues/03-other-layouts.md) — No approach meets all six needs. firstmate and Johnny.Decimal come closest, and need 5 (close a goal) is the weakest everywhere. Backlog.md dropped its dot because the hidden folder broke file references (`back-105`). OpenRig and firstmate layer a general file under the specific one. OpenRig, Spec Kit and Backlog.md keep the folder path out of their instructions. No tool uses expedition, errand or `general`. PARA and Johnny.Decimal say "area" for standing work. Ready rules: "has an end" (PARA) and "prefer the most specific zero" (Johnny.Decimal).
- [Decide the names of the work records](issues/04-names.md) — Top folder `work/`. A long goal's folder is an **initiative**. `general` has its shape but is not one: no destination, never closes. A one-off is an **issue** with no map, in `issues/` beside `wayfinder-maps/` ("map" is a game word). Memory is `wiki/`. "Expedition" and "errand" are dropped. The rule: a name says what the thing is, means one thing here, is known outside, and is not a game word. (The initiative was later dropped.)
- [Decide what a wiki holds and what it never holds](issues/05-wiki-contents.md) — The repo has one wiki, not one for each initiative, so no write needs a choice of wiki. It follows the Wiki section of the chief-of-staff skill as written: page kinds, history voice, ingest, query and lint, and the agent writes. A map and a ticket are sources that a page cites. A change to the skill needs a reason from this repo. The layout ticket decides where the wiki is and how its index shows one initiative.
- [Decide the layout of the folder](issues/06-layout.md) — **Workstream** replaces "initiative": it may close but need not, and `general` is one. The top level is fixed: `work/wiki/`, `work/plans/`, `work/workstreams/<name>/` and `work/_closed/` (only the 19 old closed maps). A workstream has `workstream.md`, `wayfinder-maps/`, `issues/` and `assets/`. A one-off issue is a file `issues/NN-<slug>.md`. `map.md` gets a `Status:` line. Closed workstreams and maps stay in place for now. Plans land in `work/plans/`, and a plan that waits becomes an issue. Every map is in a workstream. (The workstream tier was later dropped.)
- [Decide which maps go where](issues/07-maps-to-expeditions.md) — Six workstreams by subject: `long-play`, `dashboard`, `code-health`, `state-machines`, `agent-workflow` and `general`. The 17 maps are placed, and four get `Status: closed`. `retro-issue-bucket` stays a map. `autoplay-follow-ups`, `state-machines-work`, `story-scroll-back` and the four plans become one-off issues, and the new ones get `needs-triage`. No workstream has a done condition. (The workstreams were later dropped, and the rest holds.)
- [Decide where the names are written and how skills find the folder](issues/08-names-in-docs-and-skills.md) — The tracker doc defines the names, the layout tree and one status table (workstream, map, ticket, one-off issue). `AGENTS.md` names `work/` and the tracker doc. Skills point at the tracker doc for the folder rule. A path to one specific record stays as a citation, and the move rewrites it. Upstream skills are not edited: the tracker doc says that `.scratch/` in them means `work/`.
- [Decide the link check, the broken links of today and the old path](issues/09-link-check-and-old-path.md) — A new `scripts/validate_work_records.py` runs in the gate. It fails on broken relative links in live records under `work/` (not assets, not `_closed/`), and on stale backticked `work/` paths in `AGENTS.md`, `docs/` and skills. The move fixes the 17 broken links in maps and tickets, leaves the 215 in assets and `_closed/`, and checks that no working link breaks. `.scratch` goes at once, with no symlink. An old-to-new path table replaces it. No check for a stray `.scratch/`.
- [Decide what a workstream is for, or drop it](issues/11-workstream-purpose.md) — The workstream tier goes. It rested on a misreading: in the skill, a chief is a session with a goal, and several chiefs can share one wiki with no folder of their own. A goal is not a map. The layout is `work/wiki/`, `work/plans/`, `work/wayfinder-maps/<map>/`, `work/issues/` and `work/_closed/`. One-off issues sit in `pending/`, `ready/`, `in-progress/` and `closed/`, with no `Status:` line, and keep a number unique across `work/issues/`. A script moves an issue and rewrites its links.
- [Build the move to `work/`](issues/10-build-the-move.md) — Built on 2026-11-12 from [the build plan](assets/build-plan.md). All records are in `work/`, and `.scratch/`, `docs/plans/` and the `plans` symlink are gone. No link that resolved before the move broke. The gate step `validate-work-records` checks the links, and `scripts/move_issue.py` changes the status of a one-off issue. The full build passed. Old paths map through [path-moves.md](assets/path-moves.md). Not committed yet.

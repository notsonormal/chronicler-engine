# Map: turn state model

Labels: wayfinder:map

## Destination

A written model of a turn's states, the writers of game state, and the part of a turn each retry form re-runs, checked against the code. It ends with one decision: targeted fixes or a rewrite of the turn pipeline. The way is clear when a plan can be written from the model with nothing left to decide.

## Notes

- **Plan, don't do.** Tickets produce decisions. The fixes go to a plan written after the map.
- **Domain:** the action pipeline (`src/application/pipeline/`), `MessageService`, `GenerationGate`, `arrival_service.rs`, and their storage of Messages, Swipes and Snapshots.
- **Seed:** [three pipeline defects with one root](assets/seed-evidence.md), from the doc-spec boundary work. Read it before charting.
- **Current docs:** `docs/diataxis/reference/game_flow.md`, `docs/diataxis/explanation/storage_design.md`, `docs/diataxis/explanation/two-state-channels.md`, and the Message, Swipe, Retry and Snapshot entries in `CONTEXT.md`. Specs: `docs/specs/swipe_new.md`, `swipe_switch.md`, `retrigger.md`, `actions.md`.
- **Prior work:** the closed map [guided generations architecture](../_closed/guided-generations-architecture/map.md) reshaped narration turns and steering replay.
- **Skills:** `/grilling` and `/domain-modeling` for decisions and terms; `/codebase-design` for module shape.
- **Research first.** The research tickets (04–16) collect the code facts before the grilling tickets. Each writes `assets/research-NN-<slug>.md` and labels each fact known, inferred, or tested. A grilling session reads the assets of the tickets that block it, and does not grill the user on facts that the code answers.

## Decisions so far

- [Research: trace the Snapshots each generation path saves](issues/04-research-trace-generation-snapshots.md) — a generation's pointer is set once, before the Quantifier (Narration) or before reconciliation (event); a free-action Input points at the claim save with a stale `last_trigger`; arrival never persists `Generating`. [Asset](assets/research-04-generation-snapshots.md).
- [Research: list the game-state writers and the slot each holds](issues/05-research-game-state-writers.md) — many writers hold no slot, and every write goes to the process-global `Storage::game_id()`; nine concurrent pairs can lose an update; `heal_stale_if_changed` assumes the slot owner is the only writer of `Generating` and that its copy is current. [Asset](assets/research-05-game-state-writers.md).
- [Research: map what each retry form restores and re-runs](issues/06-research-retry-tails.md) — five Retry forms share one entry; re-impersonate runs the full tail by an owner decision, so `swipe_new.md` I.6 and 22.1 are stale; the main-Retry anchor is the last Input row in the history, which rewinds a continue or post-impersonate Retry to an earlier Action. [Asset](assets/research-06-retry-tails.md).
- [Research: list the readers of the Message history and its Snapshot pointers](issues/07-research-message-history-readers.md) — only three sites read a `snapshot_id` (`switch_swipe`, `retry_last_response`, `check_retry_anchor`); no HTTP path reads one, so every render shows the latest Snapshot; every history-carrying prompt reads `text` and `message_type` only, so all `System` Messages reach the LLM; `check_retry_anchor` validates a pointer the event redo does not restore. [Asset](assets/research-07-message-history-readers.md).
- [Research: trace the location header from write to render](issues/08-research-location-header-lifecycle.md) — the header is a change marker on the Swipe of the generation that moved, display-only; the mismatch is exactly that one Swipe class (its Snapshot is the pre-move state), reachable only through a Retry that left 2+ Swipes. Option B needs four missing pieces, not one: no Swipe points at the result Snapshot, there is no "room before" to diff against, name resolution is unreachable from HTTP, and the story log loads no per-Swipe Snapshot. Option B fixes the display only — option A is the only one that changes what `switch_swipe` restores. `pending_location` is a bootstrap seed only; `docs/plans/subplan-c-mapless-enablement.md` is stale and contradicts the shipped ticket-15 behaviour. [Asset](assets/research-08-location-header.md).
- [Research: route each System notice to an existing channel](issues/09-research-system-notice-channels.md) — ticket 02's five sources are complete; no source sets `GenerationStatus::Error`, so the status line carries none of them today; the banner only ever carries a failed LLM attempt (so it cannot carry the no-agent source at all) and ages out after 50 rows engine-wide; the log carries two sources at `warn!`, one at a filtered-out `debug!`, and two not at all; deleting the variant needs a migration, because the mapper's `?` inside the row loop silently blanks a legacy Game's whole history. [Asset](assets/research-09-system-notices.md).
- [Research: survey the pipeline's shape for the fix-or-rewrite decision](issues/12-research-pipeline-shape.md) — ten entry paths run through five ordering functions; `PipelineRun` holds phases but no order; the event tail is written twice and the target append three times; arrival re-implements narration; pointer timing is set by phase order, not by one module; 108 commits (63 refactors) and a reshape about monthly; most fixed and open defects share the pointer-timing or writer root; five open `architecture-deepening` tickets cover the same modules; Retry tests hand-seed a save order that has drifted. [Asset](assets/research-12-pipeline-shape.md).
- [Research: how SillyTavern binds state to swipes, retries and notices](issues/13-research-sillytavern-swipe-state.md) — one Message row owns `swipes[]`/`swipe_info[]`/`swipe_id` and an out-of-range `swipe_id` is the in-flight marker; only regenerate deletes (the last row, in memory), only the last row is regenerable, and a swipe prompt is history minus the target; `swipe()` never touches `chat_metadata`, so variables and chat-id-keyed stores survive a switch; a checkpoint or branch is the only full copy (messages plus `chat_metadata`, with a fresh `integrity` slug); the writer guard is the client-side `is_send_press || is_group_generating` with no server lock, and the stale-save guard is the integrity slug, not the generation; `is_system` rows are filtered by the prompt builder only, `IGNORE_SYMBOL` hides a row in place, and errors never become rows; core stores no location — the nearest datum is a per-chat background file chosen by one quiet LLM call. [Asset](assets/research-13-sillytavern-swipe-state.md).
- [Research: how Marinara Engine binds state to swipes, retries and notices](issues/14-research-marinara-swipe-state.md) — Marinara keys every state store that must rewind by the pair `(messageId, swipeIndex)` (`game_state_snapshots`, `spatial_context_snapshots`, `game_engine_state`); a message row is only a cache of the active swipe; a regenerate adds a swipe and cuts the tail from the prompt only, never from storage; a swipe switch restores that pair's row and replays the swipe's `macroVariableChanges`, and moves the chat-global inventory only when it is still exactly what the outgoing telling left; one generation per chat (`409`) with tracker runs outliving the reply on a separate map; failures are SSE toasts or a field on the message's `extra` (`gameDiceTurn`, never sent to the model), while stored membership notices DO reach the prompt; location lives per telling and never in the transcript — the move is written into the player's own text as `*moves to <place>*`. [Asset](assets/research-14-marinara-swipe-state.md).
- [Research: map the test coverage of generation states and retry forms](issues/10-research-test-coverage.md) — 79 coverage rows, 66 with a state-asserting test; no test ever loads a Snapshot pointer back and compares the restored world, and the two tests named for the `S0`/`S4` saves assert only that *a* Snapshot exists; the seed's two "would go red" tests do not exist, and 22.1's "the player has not moved" has no assertion at all — the HTTP apps pass an empty `AgentRegistry`, so every unseeded turn runs on `QuantifierResult::default()` (no movement, no NPCs, plus a trailing `[System] NPC detection uncertain` row) and hides the quantifier a retry form wrongly re-runs; arrival interleaving, the `/status/reset-generating` route and eight of nine concurrent-writer pairs are unreached. [Asset](assets/research-10-test-coverage.md).
- [Research: check the docs and prior decisions against the code](issues/11-research-docs-and-prior-decisions.md) — 44 claims checked: the docs are right about intent and loose about mechanism, and only `storage_design.md` §Per-swipe state binding is wrong in intent, where the owner already ruled the code at fault; `swipe_new.md` I.6/22.1 (re-impersonate runs the full tail, confirmed by test), 10.2, I.2 and I.3, `retrigger.md` I.3/13.2, and the `CONTEXT.md` Retry, Swipe, Snapshot and Game entries are stale or loose — an event redo and a retrigger do run a reconciliation Quantifier pass, but the pass cannot move the player, so each scenario's room claim holds and its reason does not; 18 prior decisions bind the model, and `gg01`'s "snapshots are captured pre-tail" ruling **conflicts** with the owner's per-Swipe ruling, so that conflict is the model's first question; `gg03`'s entry-time preset pin is superseded by `NarrationGeneration::resolve_preset_choice`; no ADR exists and `CONTEXT.md` has no generation entry. [Asset](assets/research-11-docs-and-decisions.md).

# Research 02: the concepts in `src/domain/`

Ticket: `issues/02-research-domain.md`. Map: `map.md`.
Method: bottom-up. I read the code first, then named the shapes. I did not open any `research-*.md` asset.
Labels: **known** = the code or a doc says it, or the match is exact. **inferred** = I read it from the code and the name fits. **guessed** = I am not sure the name fits.
Terms follow `CONTEXT.md`. "Npc" in a code name is the code's word for a Character.

## 2. Meeting points

Each one is a question. I do not judge.

1. **Parse a string strictly or leniently?** `LlmBackendType::from_str` refuses an unknown name and says why ("a silent `Mock` fallback would serve canned text", `llm_backend.rs:23-31`). `NarratorMode`, `NarrativePerspective` and `NarrativeTense` give a strict `FromStr` (`settings.rs:72-82, 193-203, 231-241`) and also a `parse_or_default` that logs and falls back (`:54-59, 185-190, 223-228`). `PresetType::try_from` is strict (`prompt_preset.rs:39-51`). `default_display_name` passes an odd value through (`utils/game_name.rs:18-21`). What decides which kind of parse a type gets? Why does the first group keep both forms?
2. **Is an illegal state made unrepresentable, or repaired?** `Generation` holds only the data of its kind (`generation.rs:25-30`). `TextCheckSettings` can hold `Disabled` with `enable_auto_check: true`, and a rule fixes the read and the write (`settings.rs:262-279`). `Swipe` can hold `impersonate_direction` with `impersonated: false` (`message.rs:30-34`). `Message.swipes` can be empty (`message.rs:144`), and `ensure_valid_swipe_index` repairs the index (`message.rs:148-155`). Where does the code choose the type, and where the rule?
3. **A silent no-op or a `Result`?** `Message::set_active_swipe`, `update_active_swipe_text` and `set_stored_inputs` do nothing when the index is wrong (`message.rs:117-129, 172-177`). `text()` returns `""` for a missing Swipe (`message.rs:88-90`). `JobPlan::for_request` gives `PlanRefusal` (`generation.rs:228-273`). `apply` gives `Err` (`utils/game_rules.rs:63, 80`). A failed `walk` is dropped and turned into a dynamic room (`utils/game_rules.rs:123-133`). What is the rule for a refused write?
4. **Newtype or raw primitive for an id?** `GameId(u64)` exists (`game.rs:12-14`), and `Game.id` is `u64` (`game.rs:24`). `OfferedSet(Vec<String>)` exists (`agent.rs:143`), and `DockRecord.offered` is `Vec<String>` (`dock.rs:11`). Message ids are `u64` (`message.rs:11, 55`), room ids, Character ids and preset ids are `String` (`map.rs:39`, `character.rs:62`, `game.rs:37`). Where is a newtype worth it?
5. **Enum-keyed accessor or one field per variant?** The four preset slots live as four fields on `Game` (`game.rs:37-41`), `PresetSelection` (`:68-73`) and `NewGame` (`:113-116`), and as three fields on `ModePresetBundle` (`settings.rs:85-94`). Each has a `match` accessor (`game.rs:48-64`, `settings.rs:105-122`, `settings_defaults.rs:47-56`, `prompt_preset.rs:22-29`). `Options` is the odd slot (`prompt_preset.rs:31-36`, `settings.rs:110, 457-459`). Why not a map keyed by `PresetType`? A second question: `Kind::step`, `Kind::role` and `Generation::preset_type` use `_ =>` (`agent.rs:57-70`, `generation.rs:42-48`), and `Action::is_engine_command` uses `!matches!` (`action.rs:49-54`), while `Game::active_preset_id` and `redo` list every variant (`game.rs:48-55`, `generation.rs:313-326`). When should a new variant fail to compile?
6. **A pure rule, or one that reads the clock?** `apply` is a pure function of its inputs (`utils/game_rules.rs:41`), yet it calls `Room::new_dynamic`, which reads `SystemTime::now` (`map.rs:52-58`), and it logs with `tracing` (`:125, 179-205`). `Message::new` reads `Utc::now` (`message.rs:70`). `generate_game_name` takes the existing names as a parameter and reads the date itself (`utils/game_name.rs:6-8`). `settings.rs:321-340` passes the environment in as a function, but the zero-argument wrapper reads it anyway (`:317-319, 333-335`). Which effects does the domain take as a parameter, and which does it read?
7. **How much of storage, UI and adapters does the domain know?** The code says the layer is pure (`mod.rs:2`). Types derive `Serialize` and `Deserialize` throughout. `Message::from_db` is in the domain (`message.rs:131-146`). `EventRecord` keeps a stored key `name` (`state/trigger_context.rs:20-21`). `NarratorMode::display_label` is "the label the dashboard renders" (`settings.rs:45-52`). `allows_novel` is for askama templates (`prompt_preset.rs:99-107`). `GenerationFailureKind::line` writes for "the 240px status column" (`state/generation_status.rs:21-25`). `Step::as_endpoint_str` names an HTTP value (`:239-246`). `check_api_key_available_with` skips DeepSeek because of an adapter stub (`settings.rs:342-346`). `resolve_base_url` holds provider URLs (`:365-376`). Four files import `crate::error` (`settings.rs:12`, `llm_backend.rs:8`, `state/generation_status.rs:7`, `utils/game_rules.rs:14`). Where does the domain end?
8. **A copy of the card, or the id?** `SceneState` holds whole `NpcCard` values (`state/scene_state.rs:9`), and `apply` rebuilds them from the World (`utils/game_rules.rs:65-69`). `NpcEncounterLog` is keyed by id (`trigger.rs:50-52`). A consistency check tests that both name known Characters (`utils/game_rules.rs:254-279`). Why does one hold copies and the other ids? What happens to a stored Swipe state when the World edits a Character?
9. **Rules on the entity, or as functions on data?** `Message` and `Tail` carry behaviour (`message.rs:63-177`, `tail.rs:19-69`). `Game` carries almost none (`game.rs:47-65`). The Game rules are a module function (`utils/game_rules.rs:41`). The plan rules are an associated function (`generation.rs:227-273`). The guardrail on free functions allows them only in listed folders such as `utils` (AGENTS.md; `tests/infrastructure/guardrails/free_fn.rs`). What decides where a rule lives?
10. **Typed value or string, for the same idea?** `NarrativePerspective` and `NarrativeTense` are enums (`settings.rs:167-175, 205-213`), and `TemplateVars` holds them as `String` with the literals `"third"` and `"past"` written twice (`template.rs:21-23, 35-36, 47-48`). `AgentConfig.agent_type` is a `String` (`agent.rs:117`), and `Role` is an enum (`agent.rs:14-23`). `MessageType` and `MessageKind` both tell what a Message is (`state/message_types.rs:11-27`). Where does the string stay on purpose?
11. **Why three kind enums, and two request enums?** `Kind` (`agent.rs:44-53`, no data), `Generation` (`generation.rs:25-30`, data) and `MessageKind` (`state/message_types.rs:18-27`) describe nearly the same cases. `Generation::kind` (`generation.rs:33-40`), `write` (`:94-135`) and `redo` (`:313-326`) map between them. `Action` (`action.rs:6-20`) and `JobRequest` (`generation.rs:146-159`) both name Action, Guide, Impersonate and Options. Is each one a different layer, or one idea in two forms?
12. **Copy at creation, or live reference?** A Game binds to its World by key (`game.rs:25-27`), but it copies `narrator_mode`, perspective, tense and `options_always_on` at creation (`game.rs:34-36, 42-43`; `world.rs:29-31`). Presets are copied from `AppSettings` the same way (`game.rs:40-41`; `settings.rs:400-401`). When does a Game take a copy, and when does it read the World?
13. **Glossary words or older code words?** The glossary bans "NPC" and says "Character" (`CONTEXT.md`). The code has `NpcCard`, `NpcEvent`, `NpcEventList`, `NpcEncounterLog`, `npcs_in_area` (`character.rs:61`, `quantifier.rs:13-41`, `trigger.rs:43-52`, `state/scene_state.rs:9`). `Persona` and `PersonaCard` follow the glossary. Does the glossary rule reach type names?
14. **A sentinel value, or an `Option`/new type?** `Message::new` sets `id: 0` ("the storage's to give", `message.rs:64-67`), while Game creation uses a separate `NewGame` (`game.rs:101-118`). `JobRequest::Action("")` means Continue (`generation.rs:147, 175-177`). An empty `dynamic` string means "unset" (`character.rs:17-22`). `GenerationFailure.named` is `""` when the line names nothing (`state/generation_status.rs:128-132`). Other fields use `Option` (`character.rs:34-40`, `trigger.rs:34`). Which form is the rule?
15. **One failure shape or two?** `GenerationFailure` is a kind, a `named` part and a `raw` text (`state/generation_status.rs:125-135`). `Notice` is a `reason` and a `raw` text (`dock.rs:17-22`). The glossary says both are "a reason line, with its raw text behind a disclosure". Also, `Game.failure` stores a failure (`game.rs:44`), and `GenerationStatus::Error` holds one too (`state/generation_status.rs:17`). Is the status a derived view of the stored failure? (Outside scope: `application/games/view_query.rs:130-136` builds the status.)

- **An `Option` accessor and a `Result` accessor for the same lookup.** `get_narration_connection` and `narration_connection`: `settings.rs:488-514`.

- **Fallback chain of `Option`s.** `.or` or `.or_else` to the next best value: `prompt_preset.rs:109-116`; `character.rs:43-48`; `character.rs:17-23`; `settings.rs:325-330`.
- **Lazy record on first write.** `entry(id).or_default()` creates the encounter record when first touched: `trigger.rs:56, 61, 66`; `state/swipe_state.rs:64-68`.
- **A `HashMap<usize, bool>` used as a set.** Only `true` is ever written: `trigger.rs:41, 45, 62`.
- **Positional identity.** A Trigger is named by its Character and its place in a list: `state/trigger_context.rs:6-13`; `trigger.rs:45`; `generation.rs:123`.
- **A selected item stored as an index or id beside its list.** `Message.active_swipe_index` with repair (`message.rs:59, 148-155`); the `active_*_preset_id` fields (`game.rs:37-41`). The lookup of the active Swipe is written three times: `message.rs:80-82`, `tail.rs:20-25`, `generation.rs:312`.
- **Test-only members and `pub(crate)` rebuild constructors on production types.** `message.rs:131-146` (`from_db`); `message.rs:158-164` (`#[cfg(test)] set_event_header`).
- **Serde attributes repeated across two twin structs.** `WorldCard` and `WorldManifest` repeat the same defaults: `world.rs:17-32` and `:42-59`.
- **Error used as control flow.** `walk` builds an `EngineError::Navigation` only so the caller can drop it: `utils/game_rules.rs:123-143`.

## 4. Questions

1. Is the feature `diagnostics` on in a release build? `assert_state_consistency` is empty without it (`utils/game_rules.rs:222-241`), and `Cargo.toml` has `diagnostics = []` and `testing = ["diagnostics"]`. I did not check the default features. I do not know. If it is off, the `Contradiction` failure (`state/generation_status.rs:80-82`) may not fire from this check.
2. `Room::new_dynamic` makes the id from the clock in whole seconds (`map.rs:52-60`). Two new rooms in one second get the same id, and the second `insert` replaces the first (`utils/game_rules.rs:128-131`). Is that reachable? I did not test it. (Inferred.)
3. `evaluate_triggers` walks `npcs.values()` of a `HashMap` (`utils/game_rules.rs:172`), and `fired_trigger` takes the first match (`:85-88`). When two Triggers match, which one fires? The order of a `HashMap` is not fixed. No test in `game_rules_tests.rs` covers two matches. (Inferred.)
4. `TemplateVars::render` runs seven `replace` calls in a row (`template.rs:54-62`). A persona description that holds `{{user}}` is expanded by the later calls only if the order lets it. Is that wanted? I did not test it. (Guessed.)
5. `walk` accepts only a room the map or the overlay holds (`utils/game_rules.rs:135-144`), and any other destination, even `""`, becomes a new room (`utils/game_rules_tests.rs:283`). Is an empty destination meant to be a place?
6. `check_api_key_available_with` carries a "delete this guard" note for DeepSeek (`settings.rs:342-346`). Does the domain know that an adapter is a stub on purpose?
7. The unit-test guardrail treats `domain/model/` as the "pure domain" tier (`tests/infrastructure/guardrails/unit_test_allowlist.rs:100, 228`). Several domain files hold no test of their own (`dock.rs`, `llm_message.rs`, `utils/name_uniqueness.rs`, `utils/opening.rs`, `utils/game_name.rs`). Is that on purpose? I did not check whether tests elsewhere cover them.
8. `StoryWindow.retrigger_allowed` is stored (`story_window.rs:10`), and `Tail::retrigger_allowed` is derived (`tail.rs:61-63`). Which one do callers trust?
9. `GenerationStatus` and `RunProgress` (`state/generation_status.rs:10-18, 252-255`) sit in `domain/`, but the Job that drives them is in `application/pipeline/` (the file's own header says so). Is a type in `domain/` there because it is a rule, or because several layers share it?
10. The domain has no trait at all, yet `AGENTS.md` lists an LLM provider port in `application/ports/`. Is "ports are traits in the application layer, never in the domain" a rule of the area, or a result? I read no code outside `src/domain/` for this.

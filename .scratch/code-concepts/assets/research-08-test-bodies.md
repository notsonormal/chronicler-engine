## Meeting points

Each one is a question. The researcher does not judge them.

- **MP-1. Which fake stands behind the LLM port in a unit test?** Three fakes serve one port: the strict `ScriptedModel` (3 unit files), the lenient `MockBackend` (6 unit files), and hand-written stubs (3 files for the LLM port). One quantifier is tested twice: `agent_tests.rs` through the Agent entry with `ScriptedModel`, and `orchestration_tests.rs` through an inner function with four hand-written structs. Evidence: `src/application/agents/quantifier/agent_tests.rs:29-32`, `src/application/agents/quantifier/utils/orchestration_tests.rs:15`, `:100-108`, `:381`, `src/application/llm_recorder_tests.rs:16`, `src/test_support/scripted_model.rs:7`. Concepts C12, C13, C15.
- **MP-2. Where does a handler behaviour get its test: the unit tier or tier 1?** The same behaviour has a test at both. A direct handler call with a hand-built extractor sits beside a router `oneshot` test. Pairs: text-check save (`src/adapters/driving/http/settings/handlers/settings_tests.rs:59` and `tests/http/settings.rs:107`), set narrator (`settings_tests.rs:442` and `tests/http/settings.rs:253`), duplicate preset (`src/adapters/driving/http/prompt_presets/handlers/prompt_presets_tests.rs:98` and `tests/http/prompt_presets.rs:780`). Concepts C1, C8, C22.
- **MP-3. Where does a storage behaviour get its test?** Two homes exist: unit files in `src/adapters/driven/storage/` and `tests/storage/`. `seed_world` idempotence is tested in both (`src/adapters/driven/storage/worlds_tests.rs:68`, `tests/storage/world_storage.rs:556`). Two of five `tests/storage/` files carry `CASE` tags; three do not. Concepts C7, C32.
- **MP-4. Does a test of a "sqlite" twin add a case or only change the constructor?** In `tests/storage/`, 20 tests have a `test_sqlite_` name. `test_seed_world_keeps_id_and_dependents` and `test_sqlite_seed_world_keeps_id_and_dependents` have the same body; one builds `Storage::new_in_memory()` and the other `create_test_storage(1)`. Both are SQLite `:memory:`; the second also seeds one Game row. The same holds for the duplicate-name pair. Evidence: `tests/storage/world_storage.rs:431`, `:657`, `tests/storage/preset_storage.rs:584`, `:600`, `tests/helpers/fixtures.rs:7-11`, `src/adapters/driven/storage/core.rs:123-126`. Concepts C10, C33.
- **MP-5. Which constructor builds a test storage?** Five are in use: `Storage::new_in_memory()` (131 uses in unit files, 17 in `tests/`), `empty_sqlite_storage()` (5 and 121), `create_test_storage(id)` (17 in `tests/`), `Storage::new_sqlite(pool)` over a `:memory:` pool (20 and 5), and `sqlite_storage()`. The local wrappers `create_storage()` and `sqlite()` rename them again. Evidence: `src/adapters/driven/storage/core.rs:123`, `src/test_support/fixtures.rs:427`, `:475`, `tests/helpers/fixtures.rs:7`, `tests/storage/preset_storage.rs:14`, `tests/storage/transaction_storage.rs:14`. Concepts C10, C17.
- **MP-6. Two ways to wire a test app: the test builder or the composition root?** `TestAppBuilder` and `make_test_job_deps` build the app by hand. `build_app_graph_for_tests` and `build_app_graph` use the production wiring. Tier 1 uses both. Evidence: `tests/http/support/app_wiring.rs:61-76`, `:79-94`, `src/adapters/driving/http/settings/handlers/settings_tests.rs:29`, `src/adapters/driving/http/prompt_presets/handlers/prompt_presets_tests.rs:29`, `src/bootstrap/wiring.rs:180`. Concepts C4, C8, C16.
- **MP-7. Is a test fresh, or does it hold a process-wide lock?** Each test builds its own `:memory:` storage. Still, `SettingsTestGuard` (a static `Mutex`) is taken 66 times in tier 1 (20 in `settings.rs`, 42 in `prompt_presets.rs`, 4 in `failure_display.rs`), and `ApiKeyEnvGuard` guards the env var tests. Which global state does `SettingsTestGuard` guard today? The researcher found no static settings state in production code (grep of `static` in `src/`). Evidence: `tests/test_utils/settings_guard.rs:5`, `tests/http/settings.rs:108`, `tests/http/failure_display.rs:476`, `src/test_support/env_guard.rs:5`, `src/bootstrap/wiring_tests.rs:180`. Concepts C16, C37.
- **MP-8. How does a test wait: latch, poll, event or sleep?** The hold latch and `Barrier` give exact control (`tests/http/races.rs:26-30`, `:84`). `wait_idle` polls every 15 ms (`tests/http/support/http_requests.rs:102-113`). The htmx counter waits on an event (`tests/test_utils/htmx_settle.rs:25-38`). Real sleeps remain in `tests/http/requires_migration/text_check.rs:29`, `tests/llm/flow_llm_tests.rs:38`, `src/adapters/driven/storage/llm_messages_tests.rs:76` (a 10 ms sleep so that two timestamps differ). Concepts C36, C38.
- **MP-9. A missing prerequisite: panic, skip by `return`, or `#[ignore]`?** `wait.rs` says "never a soft skip" and `run_branches.rs` panics when no World is seeded. `flow_llm_tests.rs` prints "Skipping" and returns when the API key is absent, and also carries `#[ignore]` on the same tests, so the early return runs only after the ignore is lifted. Evidence: `tests/test_utils/wait.rs:37-40`, `tests/bootstrap/run_branches.rs:76-83`, `tests/llm/flow_llm_tests.rs:50-53`, `:73`. Concepts C39, C40.
- **MP-10. The ambient clock in a fixture: `Utc::now()` or a fixed time?** Fixtures use `chrono::Utc::now()` (`src/application/narration/narrator_tests.rs:123`), while other tests use fixed RFC 3339 strings (`tests/storage/transaction_storage.rs:11-12`) or a real sleep to order rows (`src/adapters/driven/storage/llm_messages_tests.rs:76`). Files that call a clock: 10 unit files and 7 files in `tests/` (most of those use `Instant` for timeouts). No test pauses time. Concepts C38.
- **MP-11. Test helpers: shared or copied in each file?** `state_in`, `event_record`, `swipe`, `new_game` and `tail_after_one_message` are written again in several files. `state_in` appears in `src/domain/model/generation_tests.rs:18`, `tail_tests.rs:12` and `tests/storage/story_storage.rs:41`. `event_record` appears in 4 files. `NewGame` is built in full in `tests/storage/story_storage.rs:23` and `transaction_storage.rs:18`. `messages_of` is defined in `tests/http/races.rs:177` and `autoplay.rs:51`, while `story_of` lives in `support` (`tests/http/support/http_fixtures.rs:20`).

## 2. Meeting points

Each one is a question. None is a ruling.

**MP-1. Five ways to answer for "the model is not a real model". Which one does a test choose, and by what test?**
`ScriptedModel` is strict and scripted per role (`src/test_support/scripted_model.rs:1-8`). `MockBackend` is the lenient runtime provider (`src/test_support/scripted_model.rs:7`). `SilentModel` is a TCP listener that never answers (`tests/test_utils/server.rs:284-311`). `StubServer` fakes the whole engine (`tests/test_utils/stub_server.rs:242`). The recorder also takes a no-op save fn (`src/test_support/fixtures.rs:551`). The tier table says the unit tier fakes the LLM with `MockBackend` (`tests/STRATEGY.md:15`), but the three seam contracts import `ScriptedModel` (`src/application/agents/options/agent_tests.rs:15`, `src/application/narration/narrator_tests.rs:23`, `src/application/agents/quantifier/agent_tests.rs:16`). `tests/http/settings.rs:10` still uses `MockBackend` in tier 1.

**MP-2. Three fixture styles for the same domain things (Object Mother, Test Data Builder, free fn). Which one is the default for a new fixture?**
`TestNpc::named` (`src/test_support/fixtures.rs:91`), `make_npc` (`src/test_support/quantifier.rs:22`) and an inline `NpcCard` in the builder (`src/test_support/test_data_builder.rs:75`) build the same shape. `make_room` (`src/test_support/quantifier.rs:10`) and `TestMap::room` (`src/test_support/fixtures.rs:153`) do the same. `tests/helpers/storage_ext.rs:7-12` adds a fourth style, an extension trait on `Storage`.

**MP-3. Four ways to put a Game row into storage in a test. Which one is the arrange path, and why may two of them skip the storage layer?**
`seed_default_game_row` writes raw SQL (`src/test_support/fixtures.rs:413-425`). `seed_game_row` calls `Tx::write_game_row` under the backend lock (`src/test_support/fixtures.rs:463-473`). `TestAppBuilder` seeds the opening Message through a unit (`src/test_support/test_app_builder.rs:122-144`). The shared SQLite fixture pre-seeds a Game with id 1 (`src/test_support/fixtures.rs:427-431`). `test_new_game` hard-codes preset ids (`src/test_support/fixtures.rs:451-454`), while `seed_default_hook_presets` reads the same ids from constants (`src/test_support/context.rs:61-82`).

**MP-4. Strict versus lenient doubles meet one more time: should an unscripted call fail where it happens, at drop, or in a later read?**
The fake returns an error and records the stray call (`src/test_support/scripted_model.rs:196-207`). Its drop panics (`src/test_support/scripted_model.rs:262-268`). A tier-1 helper also scans the stored failed attempts for the marker text (`tests/http/support/http_requests.rs:128-136`, `src/test_support/scripted_model.rs:24`). One signal, three checks.

**MP-5. Two registries of seam contracts. What keeps them equal?**
The Rust list holds three files (`tests/infrastructure/guardrails/unit_test_allowlist.rs:91-96`). `scripts/validate_seam_cases.py:23-24` scans every `src/**/*_tests.rs` and `tests/storage/`. The strategy names five kinds of box: storage, LLM providers and transport, the Harper text checker, each Agent, the `Narrator` (`tests/STRATEGY.md:36-39`). The legacy list still holds the storage, provider and Harper test files (`tests/infrastructure/guardrails/unit_test_allowlist.rs:8-26`).

**MP-6. The legacy list holds `domain/model/` files that the pure-domain prefix already allows. Is the list meant to hold them?**
15 of 78 entries start with `domain/model/` (for example `tests/infrastructure/guardrails/unit_test_allowlist.rs:69`). The check lets any `domain/model/` file pass (`tests/infrastructure/guardrails/unit_test_allowlist.rs:100`, `tests/infrastructure/guardrails/unit_test_allowlist.rs:228`). The stale check tests only that a file exists (`tests/infrastructure/guardrails/unit_test_allowlist.rs:187-196`).

Stale-entry checks: `tests/infrastructure/guardrails/unit_test_allowlist.rs:187-207`, `tests/infrastructure/guardrails/walkers.rs:94-109`, `tests/infrastructure/guardrails/mod.rs:164-190`.

## 2. Meeting points

Each is a question. None is a ruling.

- **MP-1. Why do two outbound systems sit behind an application port and the third (storage) does not?** `src/application/ports/mod.rs:4-5` lists `llm_provider` and `text_checker` only. `storage/core.rs:16` is a concrete `Storage`. 9 non-test files under `src/application/` import the storage module (grep): e.g. `src/application/generation/gate.rs:150` builds a `TxToken`. The fault-injection layer (concept 9) and the in-memory constructor (concept 11) look like the storage answer to "how do tests replace the adapter". Concepts in play: 1, 5, 7, 9, 11.
- **MP-2. Which seam does the repo use to replace an adapter in a test: a fake behind the port, or a layer inside the type?** LLM: `MockBackend` behind the port, in the production tree, chosen by config (`llm/providers/mod.rs:5`, `src/bootstrap/wiring.rs:36`). Storage: `BackendKind::Test` inside `Storage` (`storage/core.rs:74-86`). Text check: no fake in the area. Concepts: 8, 9, 11.
- **MP-3. Which writes get which atomicity mechanism?** Three exist: (a) a lock-held closure for read-modify-write (`storage/settings.rs:106-115`); (b) an explicit SQL transaction in `write_world` (`storage/worlds.rs:175-182`) and in migrations (`storage/utils/plumbing.rs:57-61`); (c) the `Tx` unit with a token (`storage/transaction.rs:305-327`). Two multi-statement writes use none of them: `update_world` writes the world row then the map row with no transaction (`storage/worlds.rs:314-333`, while `write_world` at `:177-178` has one), and `save_llm_message` inserts then prunes (`storage/llm_messages.rs:19-46`). Concepts: 19, 20.
- **MP-4. How does the code choose between a constraint, a scan and a count-check for a "name is taken / key is in use" rule?** World key: the `UNIQUE` constraint is "the authority" (`storage/worlds.rs:188-190,240-243`). Preset name: a scan inside the lock, not a constraint, "so a legacy database that already holds duplicates still opens" (`storage/presets.rs:65-68`). World delete: a count of Games, then delete, with no foreign key to refuse (`storage/worlds.rs:377-388`). Preset in use: `count_games_using_preset` (`storage/games.rs:149-171`). Child rows: `ON DELETE CASCADE` (concept 26). Concepts: 19, 26.
- **MP-5. Why do five mapping styles from row to domain exist?** (a) `DbX::from_row` plus an inherent method with three names: `to_game` (`storage/models/game.rs:53`), `to_card` (`storage/models/character.rs:50`), `into_preset` by value (`storage/models/prompt_preset.rs:39`), `to_settings` (`storage/models/settings.rs:41`); (b) `TryFrom` impls in `mappers/` (`storage/mappers/message.rs:29,45`; `storage/mappers/llm_message.rs:10`); (c) `FromSql` impls on domain types (`storage/mappers/message.rs:15-27`); (d) an inline closure (`storage/stories.rs:253-272`); (e) serde straight into a domain type (`storage/stories.rs:243,348`; `storage/docks.rs:38`). Column reads are positional (`storage/models/game.rs:32-49`) in every row struct but `DbWorld`, which reads by name (`storage/models/world.rs:27-41`). Concepts: 4, 35.
- **MP-6. When does a bad stored value become a default and when an error?** Lenient: `NarratorMode::parse_or_default` and the two siblings, in `storage/models/game.rs:63-72` and `storage/models/world.rs:56-65`. Strict: `PresetType::try_from` returns `EngineError::Parse` (`storage/models/prompt_preset.rs:40-41`); `MessageType` through serde returns `Err` (`storage/mappers/message.rs:49`). Concept: 35.
- **MP-7. Why are some column lists derived from a const and others repeated as literals?** Derived: `WORLD_COLUMNS` (`storage/worlds.rs:400-412`, whose doc says "a new column is listed here once"), `ENTRY_COLUMNS` (`storage/stories.rs:19-24`). Repeated: the 18-column Game list appears in `storage/games.rs:16` and `:62` and again, by position, in `DbGame::from_row` (`storage/models/game.rs:30-51`); likewise `storage/characters.rs:17,34`; `storage/personas.rs:16,33`; `storage/presets.rs:17,44,127`; `storage/settings.rs:28,70`. Concepts: 30, 16.
- **MP-8. What is the contract between a domain type's serde shape and the stored format?** Domain types go into JSON columns with their own `Serialize` (`storage/transaction.rs:169,196` for the Swipe state and maker; `storage/models/character.rs:22` for `Vec<Trigger>`). Twice the domain shape changed and the migration deleted every Game: v28 (`storage/utils/plumbing.rs:662-665`) and v30 (`:716-726`, "the Games the older code saved cannot be read"). Concepts: 4, 24, 25.
- **MP-9. What decides between an additive, guarded migration and a destructive one?** Additive and re-runnable: v12, v15, v16, v18 (`storage/utils/plumbing.rs:251,282,290,309`). Destructive: v28 and v30 delete all Games (`:667-671,719-722`). Reversal: v21 drops two Game columns (`:469-476`), v23 restores them (`:507-518`). Concept: 25.
- **MP-10. When does the adapter stamp the time, and when does the domain give it?** Adapter: `Utc::now()` at 10 sites (concept 34). Domain: the Message timestamp is written as given (`storage/transaction.rs:121`); `LlmMessage.created_at` comes from the domain through the mapper (`storage/mappers/llm_message.rs:49`). Parsing time also varies: the helper `parse_datetime` (`storage/utils/plumbing.rs:8-15`) serves `storage/models/game.rs:61` and `storage/stories.rs:258`, while `storage/mappers/message.rs:51` and `storage/mappers/llm_message.rs:14` parse inline with their own error text. Concepts: 34, 35.
- **MP-11. When do several reads share one lock acquisition, and when does each take its own?** The story window reads under one connection, "so no write lands between them" (`storage/stories.rs:53-54`, `:59-61`). `world_bundle_for` calls `require_game`, `require_world`, `require_persona`, `list_characters`, each taking the lock (`storage/worlds.rs:127-135`), so it is not one snapshot. In the story area, `window` uses one JOIN (`storage/stories.rs:214-247`), while `messages` and `read_tail` load per id, two queries per Message (`storage/stories.rs:117-127,304-314`). Concepts: 18, 19.
- **MP-12. Which write path owns which table?** `games` is written by direct `Storage` methods (`storage/games.rs:34,119`; `storage/core.rs:241`), by the create unit (`storage/transaction.rs:66-95`), and by the failure line inside a unit (`storage/transaction.rs:205-220`). Docks are read through `DockReads` and written only in `Tx`. Settings, presets, personas, worlds and `llm_messages` write directly. Concepts: 20, 23.
- **MP-13. What is the rule for who wins between the data files and the database at boot?** Settings: "after the first run the database outranks `data/settings.json`" (`storage/settings.rs:118-123`). World: "replacing an existing world's data is intended" (`storage/worlds.rs:144-146`), and the world row id survives. Character and Persona: `INSERT OR IGNORE` (`storage/characters.rs:59`; `storage/personas.rs:62`). Inferred: after a world is re-seeded, an edited Character file does not reach a database that already holds that Character. Concept: 28.
- **MP-14. Where do rules live: in the storage adapter or in a service?** Name uniqueness runs inside storage and returns `EngineError::Validation` (`storage/presets.rs:91-109`, calling the domain `name_is_available`). `delete_world` refuses when Games exist (`storage/worlds.rs:384-388`). Retention of 50 rows is a storage constant (`storage/llm_messages.rs:11`). `WorldBundle` builds domain read views (`game_world`, `view`) inside the storage module (`storage/worlds.rs:35-55`). Concepts: 7, 19.
- **MP-15. Why does the provider adapter import an application function that is not a port?** `llm/providers/ollama.rs:9` and `llm/providers/openrouter.rs:9` import `application::prompting::prompt_merge::merge_single_user_message`, while the same files import the port at `:8`. ### Hazards seen (inferred, not tested)

- `llm/transport/utils/response.rs:140-142`: `&error_body[..500]` slices a `String` by byte. A multi-byte character that straddles byte 500 would panic.
- `utils/harper.rs:25-40`: if `char_span.start` equals the number of characters (a zero-width lint at the end of the text), no loop step matches the start and `byte_start` falls back to `0`. The span then covers the whole text.
- `llm/transport/utils/response.rs:46-56`: an API error in a body with HTTP 200 is recorded as `LlmFailure::Http { status: 200, ... }`. A reader that keys on the status sees a success code on a failure.
- `llm/providers/mock.rs:78`: `raw_response_json` is built with `format!` and an unescaped `text`. A narration with a quote makes invalid JSON in the forensics record.
- `storage/worlds.rs:314-333`: `update_world` is not atomic across the world and map writes (see MP-3).
- `storage/transaction.rs:47-48`: a `Storage` call inside a unit closure would block forever on the std mutex. Nothing in the types prevents it.
- `llm/providers/deepseek.rs:25-30`: a connection of provider type DeepSeek can be saved and chosen, then fails on each call.

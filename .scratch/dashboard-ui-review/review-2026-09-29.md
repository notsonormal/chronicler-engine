# Dashboard UI review — 2026-09-29

## Scope and method

- Engine: `cargo run -- --world redmist_estate --port 3200`, active game `Redmist Estate_2026-09-29_1`.
- Browser: headless Chrome 154, desktop viewport 1280x800 (primary target), plus one 480x860 check.
- Every tab visited; Game tab exercised through one real turn, edit mode, slash menu, the log-entry text check, and the error state.
- Screenshots: `tmp/ui-review/NN-*.png` (numbers cited below). `tmp/` is gitignored, so they exist only on the machine that ran the review. Contrast ratios computed in-page with the WCAG formula.
- Epistemic tags: **[known]** = observed or measured; **[inferred]** = follows from code, not exercised.

**Data change:** one turn was added to the active game (player input "I look around the gates" + narration). Nothing else was saved. The error state was rendered by injecting the server's real error markup into `#status-display`, not by changing your connections.

**Not covered:** text-check-enabled flow, a real narrator failure end to end, new game / world / preset create-and-save, delete flows, swipe switching with more than one swipe, options dock with options present, the Thinking states (the turn finished too fast to capture), keyboard and screen-reader audit.

## Theme 1 — Errors and system health

This is the theme behind the toast issue. The dashboard has one loud channel (the red toast) and no quiet one. The result is that some failures are too loud and others are invisible.

| # | P | Finding | Evidence |
|---|---|---|---|
| 1.1 | P1 | **Degraded backend is invisible.** On the turn I ran, the Quantifier connection (`ollama-gemma-4-e2b`, `http://localhost:11434`) failed twice and the engine used fallback NPC IDs. The UI said "Ready", the header said "Connected", and the Settings card showed nothing. | [known] engine log `[Quantifier] All attempts failed, using fallback NPC IDs`; `02` |
| 1.2 | P1 | **LLM Messages omits failed calls.** The panel lists only the successful narrator call; the two failed Quantifier requests (`req:2`, `req:3`) are absent. The one diagnostic screen cannot show the failure. | [known] `17`, engine log |
| 1.3 | P1 | **Header "Connected" is hardcoded.** It never changes (also noted in `.scratch/test-strategy-execution/issues/14-browser-missing-tests.md`). It reads as a live health signal but isn't one. | [known] |
| 1.4 | P2 | **Toast shows raw transport text and covers the header.** Example: `Error: LLM network error contacting http://localhost:11434/v1/chat/completions: Request failed: error sending request for url (...)`. It hides the game name and connection status and suggests no next step. | [known] `03` |
| 1.5 | P1 | **Status-display error has no width limit.** The error string pushes the command input from ~1020px down to 235px. | [known] `04` |
| 1.6 | P2 | **Generation errors show twice.** The status display already holds `Error: …`; the toast repeats it. | [known] |
| 1.7 | P2 | **Silent failures.** `submitEdit`, `submitNewSwipe`, `submitRetrigger` check neither `response.ok` nor `.catch`, so a failed edit, new swipe, or retrigger shows nothing. | [known] `assets/index.html` |

Direction (from the earlier discussion, option B): route by kind. Persistent/background problems become a steady state in the header (connection + per-role health: Narrator / Quantifier). Generation errors live only in the status display, clamped to one line with a "details" affordance. User-action errors show inline next to the action. The toast is retired or reserved for rare one-off events.

## Theme 3 — Visual language and readability

| # | P | Finding | Evidence |
|---|---|---|---|
| 3.1 | P2 | **Dialogue is rendered in the error red** (`rgb(255,68,68)` = `--color-accent-red`). `ui_design.md` specifies orange `#ffb347`. Red speech reads as an error and fails contrast: **3.6:1** on the narration bubble (AA needs 4.5:1). | [known] |
| 3.2 | P2 | **Small grey text fails contrast.** Swipe counter / timestamps `#888` on `#1a3a3a`: **3.46:1** at 11–12px. | [known] |
| 3.3 | P2 | **Icon-only controls rely on glyphs with no fallback.** `✎` (U+270E), `🗑`, `↻` render as empty boxes in this environment; none have `aria-label` (only `title`). `▶` means both "next swipe" and "Retry" (new swipe). | [known] `01`, `16` (tofu is font-dependent; may render on your desktop) |
| 3.4 | P3 | **Neon palette on long prose.** Narration is saturated `#00ffff` on teal (9.79:1, passes) across long paragraphs, plus `#00ff00` primaries and `#ffff00` system text. High contrast, but tiring for reading-heavy use. | [known] (subjective judgement) |
| 3.5 | P3 | **NPC portraits have no name or tooltip** (only `alt`). The sidebar has a large empty area below one portrait. | [known] `01` |

`docs/diataxis/reference/frontend/ui_design.md` says: reset button in the header (it is on the Games tab), NPC portrait labels (none rendered), dialogue orange (renders red). `docs/diataxis/reference/frontend/dashboard.md` describes the error banner as the error path; it will change if Theme 1 is acted on.

## Open questions

- Should Options prompt presets be editable in the Prompt Presets tab? `data/prompt_presets/options/` exists but the tab shows only System, Quantifier, Impersonate.
- Is the neon palette an intended identity, or a default nobody chose?

## What works

- Slash menu: clean, readable, well placed (`06`). A good model for other overlays.
- LLM Messages layout: collapsible System / User / Response / raw JSON is clear (`18`).
- Games tab per-game posture and preset pickers are compact and readable (`16`).
- Destructive actions (reset game, delete connection) ask for confirmation.

## Suggested order

1. P1 bugs in Theme 2 (2.1–2.4) — small, contained fixes.
2. Theme 1 as one design change: a health/status model (header), clamped status errors, inline action errors, record failed calls in LLM Messages.
3. Contrast and semantic colour (3.1, 3.2), then icon labels (3.3).
4. Panel consistency (Theme 4) and copy (Theme 5) as a sweep.

1. Storage dispatch is a wide inherent interface, not a trait

Strong ports & adapters

Problem. ~30 inherent pub fn methods each repeat the same match backend { Sqlite=>.., InMemory=>.. }. The seam is the with_backend_mut helper plus the Backend enum, not a trait — so every new operation adds two identical arms.

Solution. Make StorageBackend a trait; SqliteBackend and InMemoryBackend become two real adapters. The test-override variant stays a third adapter wrapping the base.

  • locality: dispatch logic lives once, not per-method
  • leverage: one interface, two real adapters + one test adapter
  • interface shrinks: callers see the trait, not the enum plumbing
  • two adapters justify the seam (the design-it-twice principle)

Evidence: core.rs:117-141 with_backend_mut; core.rs:25-50 Backend/BackendKind; games.rs:10+, worlds.rs:18+, messages.rs:9+, snapshots.rs:9+. Deletion test: partial — the duality is real, the duplication is not.

Problem. arch-lint.toml forbids the HTTP layer from importing storage, so the codebase grows one-method services that only forward to Storage. PersonaCatalogue's own header admits it is "intentionally a one-method seam."

Solution. Replace the parade of delegates with a single Repository port trait that Storage implements. The HTTP layer depends on the trait; the lint rule still holds.

  • locality: storage access points stop multiplying
  • leverage: one port serves N HTTP handlers
  • delete 4 shallow wrapper modules
  • interface stays narrow per concern via sub-traits

Evidence: persona_catalogue.rs:18-25 (one method), settings_service.rs:13-23 (one method), prompt_preset_service.rs:15-31 (four delegates), world_catalogue.rs:14-52 (five delegates), arch-lint.toml:136-140 ("Server layer must not depend on storage directly"). Deletion test: partial — delegates reappear in handlers only because of the lint rule; a port trait removes that reason.

Top recommendation

Strong Start with candidate 1 — turn Storage into a StorageBackend trait.

It is the root cause of candidate 2. The layer rule exists to keep HTTP off storage internals; a Repository port trait satisfies that rule directly and removes the fleet of one-method services. Two real adapters (SQLite, InMemory) plus a test adapter justify the seam. Fixing the storage seam first shrinks the interface callers see, concentrates dispatch logic in one place, and likely retires candidates 2, 6, and part of 4 in its wake.

Sequence suggestion: 1 → 2 (largely automatic) → 6 → 4 → 3 → 5 → 7.

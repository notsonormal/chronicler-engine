Labels: wayfinder:research. For ticket [01](../issues/01-research-gate-rules-and-their-tests.md).
Date: 2026-10-29. Method: read only. No build and no test run.

**Labels.** **known** = I read the file or the test body. **inferred** = I reached it from a test body and the code. **guessed** = I did not confirm it.

## Scope

The gate means: the busy state and its holder, the writer rule, the job id check, stop, reset, delete, the Autoplay holder, the config write against a busy Game, and the Swipe state write.

Rule sentences come from `docs/diataxis/reference/game_flow.md`, sections *The Job*, *The Busy State and Its Holder*, *The Autoplay Loop*, *The Writer Rule*, *Stop and Reset*, and *The State of a Game* (**known**).

| "A part that fails ends the Job. Every transaction that landed before the failure stays." | The Job | The failure path |

## 4. Result for ticket 03

There is enough unpinned ground to justify the trial model: 19 of the 39 rule sentences are partly or not pinned, and the unpinned orders are the gate's own interleavings — a delete during a plain Job, a config write during a plain Job, the accept's read with its count, and the busy check against another check (**known**, from the table above). The three rules with no test are ownership and restart claims; a statechart model can show them, but only a restart test or a storage read can pin them (**inferred**).

One caution for ticket 03: the busy rule makes most of these orders unreachable through the HTTP routes, so the model's counterexamples are candidate tier-1 tests only where a route can reach them (**inferred**).

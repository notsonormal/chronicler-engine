# Map: the role of TLA+ models in this repo

Labels: wayfinder:map

## Destination

The role of TLA+ models in this repo, decided and in place for the gate, for three goals: (a) find bugs, (b) align the code, the specs and the docs, and (c) documentation that replaces prose (ticket 09). `verify-gate` stays. Each gap of its first run is closed or left with its reason. Its TLA+ model and the diagrams generated from it replace the gate part of `docs/diataxis/reference/game_flow.md`, which is rewritten.

- **Terms.** Use `CONTEXT.md`: Game, Job, Message, Swipe, Persona, Trigger, Autoplay run.
- **"Model" has two meanings here; never write it alone.** A **TLA+ model** is the state-machine file that TLC checks: its variables, its start state, its actions and its rules. A **model call** and the **LLM** are the language model, as in `CONTEXT.md`; `ScriptedModel` is the **LLM fake**. **Model checking** is the name of the technique that TLC runs. The two assets of tickets 01 and 02 were written before this rule and use "model" alone for the TLA+ model.
- **Skills:** `/grilling` and `/domain-modeling` for decisions; `/research` for outside facts; `/prototype` and `statechart` for the trial TLA+ model of ticket 03; `/create-formal-verification-skill` and `/statechart` for ticket 07; `/maintain-formal-verification-skill` for a maintain pass, which the agent that changes a covered function runs before it ends its task (ticket 09, Q3); `/statechart` for tickets 13 and 14; `/document-review` and `/diataxis-doc-review` for ticket 15.

## Decisions so far

- [Research: which rule sentences of the gate the tests already pin](issues/01-research-gate-rules-and-their-tests.md) — 39 gate rule sentences: 20 pinned, 16 partly pinned, 3 not pinned; the gaps are the gate's own orders (a delete or a config write during a plain Job, the busy check before another refusal, a stop that clears a failure line, the restart); the six platform-choice interleavings are all present; enough ground for the trial, but a counterexample is a test only where a route reaches it.
- [Research: how other teams tie a TLA+ model to code](issues/02-research-tying-a-tla-model-to-code.md) — five methods; for this repo, first a TLA+ model checked once with each rule carried by one tier-1 test and paired by rule id (the skill's method plus the `validate_feature_spec.py` idiom), then trace validation on `BusyRegistry::hold` as the upgrade path (the only mechanical tie; CCF found a bug that tests executed but did not assert on); TLC-in-CI alone, a TLA+ model beside the docs, and generated tests rank lower; a JDK in the build gates places 2 and 3.
- [Prototype: one TLA+ model of the gate, built from the spec only](issues/03-prototype-spec-only-gate-model.md) — no code defect; three "own id" rules (G2 in the spec, G1 in part, G3 not clear in autoplay.md); six candidate tests for orders that no test forces; 5 of 15 rules true by construction; its value is a one-time audit, and `game_flow.md` need not hold the rules it found (owner).
- [Research: tla-ts in place of TLC](issues/05-research-tla-ts-instead-of-tlc.md) — keep TLC: tla-ts agrees with TLC on eleven configs, but it writes none of the three outputs that the skill reads (the `-tool` framing, the `-dump` state graph, SANY XML); speed about equal on this host.
- [Decide the role of the statechart skill in this repo](issues/04-decide-the-role-of-the-statechart-skill.md) — the skill stays; a trial makes `.agents/skills/verify-gate/` with pstack's method: a TLA+ model made from the code, coverage by function, a sync commit; the TLA+ model is the hub of five comparisons (code, spec both ways, tests, docs), each rule quotes a gate scenario of `docs/specs/`; no new spec-only audit; `mise` with the skill's pins; a staleness warning in `build.py` only if the skill stays; gaps are reported only; ticket 09 decides from the first run.
- [Set up the toolchain and the two pstack skills](issues/06-task-set-up-the-toolchain-and-the-pstack-skills.md) — `mise` 2026.11.1 in `~/.local/bin`; its pins (TLC 2.19 / jar 1.7.4, Temurin 25.0.5) reproduce the ticket 03 report byte for byte; about 610 MB of disk, 550 MiB peak memory, 21 s a run; the two pstack skills are copied; Pele stays in `/tmp`, with its render script saved in `assets/00-code-models/`.
- [Write the verify skill of the gate, and do its first run](issues/07-task-write-the-verify-skill-of-the-gate.md) — `.agents/skills/verify-gate/` with 15 spec-quoted rules, 18 mutants (each rule fails once), 7 small configs, about 35 s a check; first run is bug: 1 code gap (a delete races a switch of the active Game), 1 model, 8 spec, 5 test, 1 doc ([trial log](assets/trial-log.md)); the cold proof run caught the scratch break only after it updated the model, so a pass means nothing until the model follows the code.
- [Decide the gaps of the first run, and the future of the verify skill](issues/09-grilling-decide-the-gaps-and-the-verify-skill.md) — map widened to three goals (bugs, alignment, documentation that replaces prose); `verify-gate` stays; a TLA+ model gets its own row in `docs/AGENTS.md`; a gap gets a scenario and a test only when a client can see a different result; the delete race has three orders (one bug ticket); `game_flow.md` is rewritten whole; an extended `/statechart` generates state charts, checked sequence diagrams and bug paths into `docs/diataxis/reference/diagrams/`; the `build.py` warning shows on every run.

## Out of scope

- **Mutation tests of the code.** The unclebob-quality-tools map owns `mutator`.
- **Storage transactions, prompts, JSON parsing, UI copy.** A TLA+ model cannot check them.

# Design the AI steering feature for chronicler_engine

Type: grilling
Status: resolved
Blocked by: 01, 02, 03

## Question

Synthesize the three research summaries (tickets 01–03) into one coherent design for chronicler_engine covering all three steering surfaces, ready for implementation tickets to graduate. Resolve each via `/grilling` + `/domain-modeling` with the human, one question at a time:

1. **Guided generation** — the prompt block format and its position in the `LayerRenderer` order (the old plan's recency-bias "after Output Format" claim is open and may be overturned by research); the threading path (`ActionForm` → `process_action`/`retry` → `pipeline_run` → `PromptContext` → `assemble`); how transience is enforced (not persisted to history); whether it applies on retry only or also new generation, and its interaction with the swipe system.
2. **Narrator Action** — whether to add a `MessageType::Narrator` variant or reuse `System`; the history-rendering format sent to the model; persistence as a permanent `MessageEntry`; the slash-command (`/narrator <text>`) entry path and how it triggers a generation.
3. **Impersonate** — how it forces the AI to write as a persona; interaction with the persona-card layer and output-format instructions (replace or augment); the slash-command (`/impersonate <persona> [text]`) entry path; threading.
4. **Prompt-layer coordination** — resolve any conflict between the three features' placements in the `LayerRenderer` order so they compose, not collide.
5. **UI** — the affordance (toggle vs slash command vs both) for each feature.

Ground each decision in the three research summaries; cite which repo's mechanism you're porting and why. The resolution is the design; implementation tickets graduate from it into the map's Not-yet-specified section.

## Decisions (in progress — grilling rounds)

Domain boundary (framing): guided generation steers **content** (what the AI says); impersonate substitutes the **speaker** (who says it). Same surface — one transient nudge — but orthogonal axes. They are distinct mechanisms, not unified.

- **Q1 — Narrator storage model: new `MessageType::Narrator` variant** (Option A, Marinara/ST). A persisted history row; the type is the discriminant. Keeps `System` meaning "engine notice" (today: `"[System] NPC detection uncertain…"`, `pipeline_run.rs:200`).
- **Q2 — Guide recency: guide is the final layer, after `<PlayerInput>`** (Option A, Marinara model). Guide wins recency over both output-format and player input. Consistent with chronicler's existing "most-recent wins" philosophy (player input already sits after output-format). Verified against Marinara `generate.routes.ts:7140` (guide pushed after fully-assembled `finalMessages`) vs ST `PromptManager.js:2085` default order `chatHistory → jailbreak` (output-format wins); chronicler chose Marinara's rule.
- **Q3 / Q3-bis — Impersonate target: player character only** (Option A, all three repos). Read destination's "specific persona" as the active persona, specifically. NPC impersonation deferred. Impersonate is NOT unified with guided-gen (Q3-bis = B): distinct mechanisms, orthogonal axes (content vs speaker).
- **Q4 — Guide retry: replay via per-swipe metadata** (Option A, Marinara `GenerationReplay`). A unified turn-conditions blob (guide + impersonate flag + direction + preset) stored on the swipe; retry re-applies it. Storage location: **`Swipe`**, not `GameStateSnapshot`. Verified `Message` has no `snapshot_id` field — `set_snapshot_id` delegates to `active_swipe_mut().snapshot_id` (`message.rs:108`); the snapshot is associated with the swipe, not the message. Snapshot stays a pure world-state freeze ("frozen game state" via `from_game_state`); steering is generation metadata, not world state.
- **Q5 — Narrator rendering in history: bare text, no speaker prefix** (Option A, Marinara-roleplay + ST convergence). Narrator line appears as scene truth. Verified Marinara roleplay/game maps `narrator` → `role: "system"`, no prefix (`generate.routes.ts:1448`); ST suppresses the name prefix for `extra.type === 'narrator'` (`openai.js:580,586`). Correction to map fog: narrator **is** in ST (`/sys` alias `/nar`), not Marinara-only. Implementation note: chronicler's `render_history_layer` currently forces a sender on every line (`sender.unwrap_or("Narrator")`, `assembler.rs:228`); the `Narrator` type branch must skip the `{sender}: ` format.
- **Q6 — Impersonate output: save as player message + replay blob** (Option A, Marinara). Generated text becomes a history row (player-voiced); the replay blob (impersonate=true + direction + preset) enables retry via swipe without deleting the player message. Verified Marinara path: impersonate saves as `user` message with `extra.generationReplay` (`generate.routes.ts:6930`); on regenerate of that user message it reads the blob, re-sets impersonate, excludes the old text from context (`:1342`), re-runs, saves new result as a swipe (`:6950`). Q6=A entails Q4=A (same blob).
- **Q7 — Impersonate prompt structure: separate `PresetType::Impersonate` preset** (Option A, Marinara `impersonatePromptPresetId` analogue). When impersonate=true, the assembler selects the impersonate preset instead of the system preset. Verified the default system preset's voice apparatus is entirely narrator-framed and contradicts impersonate: Role = *"You are an interactive fiction author… acting as the narrator, the world, and every character… except the protagonist, who is played by the user"*; WritingStyle = *"Third-person limited… focused on the player character"*; OutputFormat = *"Your only job is to narrate what happens now."* (`data/prompt_presets/system/default.json`). These are the voice itself — they must be **replaced**, not toggled. Marinara suppresses all non-marker sections (`assembler.ts:367,505`); ST/GG's additive approach is incoherent (keeps "you are the narrator" + appends "write as the user" = direct contradiction). Chronicler splits cleanly: drop voice apparatus (Role/Instructions/WritingStyle/OutputFormat), keep context layers (`<GameState>`, `<KnownNpcs>`/`<NpcsInRoom>`, `<WorldLore>`, `<ConversationHistory>`).
- **Q7b — `<PlayerCharacter>` layer under impersonate: drop the layer, inject persona into the impersonate instruction** (Option A, Marinara `DEFAULT_IMPERSONATE_PROMPT` with `{{persona_description}}`/`{{persona_name}}`). The impersonate instruction holds both "you are X" and "X is …"; the `<PlayerCharacter>` reference-card block is not rendered. Single coherent voice instruction.
- **Q8 — Guide/impersonate mutual exclusivity: exclusive per turn** (Option A, Marinara). A turn is either guided, impersonated, or plain — never both. Verified Marinara `applyGenerationReplayToRegenerateInput` strips the guide when impersonate is true (`generation-replay.ts:95-110`). Exclusivity dissolves the placement conflict (only one transient nudge ever exists, so it's always last). Composition is net-new (no ported reference) — deferrable to a later ticket.
- **Q9 — Guide application surface: new generation + retry, not retrigger** (Option A, GG + Marinara). Guide accompanies a player action (new) and replays on retry; retrigger (continue narration, no player input) does not take a guide. Old plan's "retry-time nudge" framing overturned by research — the guide is a per-turn steering instruction, and a turn begins with a new action.
- **Q10 — Command parsing: slash-command parser** (Option A, ST/Marinara/GG convention). A parser recognizes `/narrator`, `/impersonate`, `/guide` prefixes in the single `command` field and dispatches. One input box, one form field, one endpoint. Decision stands on the convention's merits across all three researched repos — NOT on the existing `Action::FreeAction` stub, which is a leftover from removed non-LLM movement and carries no weight. (The `FreeAction(String)` variant and trivial `Action::parse` will be replaced, not extended-by-habit.)
- **Q11 — Narrator entry: generate-then-add** (Option B, ST `/sysgen`). `/narrator <text>` persists the narrator message AND immediately triggers a narration generation (a continue, since no player action). Verified Marinara has NO manual narrator slash command (narrator rows are created only by automated scene/game flows in `scene.routes.ts`/`game.routes.ts`), so Marinara does not decide this; ST is the only reference, and ST splits `/sys` (add-only) from `/sysgen` (generate-then-add). B chosen over A on UX: a narrator direction that produces no response leaves the user wondering if it registered. Verified the execution path exists — empty command dispatches to `continue_narration` (`actions.rs:27-28`, `action.rs:55`). Design consequence: narrator, guide, and continue all share the "no-player-input generation" shape.
- **Q12 — Guide composition: guide replaces the player input** (Option A, GG). The input-box text IS the guide; there is no separate player action. The guide steers the next narration beat; nothing is saved to history for the turn (guide is transient, Q4). Verified continue IS implemented (empty `command` → `continue_narration`), so a guided turn runs the continue path with the guide layered on — guide-replaces-input is not a new pipeline path. Coherent with Q9's retry case (guide is the only input there too).

### Open frontier

- UI affordance per feature (toggle vs slash command vs both) — largely settled by Q10 (slash commands) + Q12 (guide = input text + trigger); remaining: does guide get a dedicated trigger button or a `/guide` slash command, and is the narrator/impersonate command discoverable beyond typing a slash?
- Prompt-layer coordination is settled by Q8 (exclusivity → no placement conflict).

## Answer

Design synthesized and recorded as asset `research/04-design-synthesis.md`. All 14 grilling questions resolved (Q1–Q14); design tree fully walked. Key decisions: new `MessageType::Narrator` variant (Q1); guide as final `LayerRenderer` layer after `<PlayerInput>`, Marinara recency model (Q2); impersonate targets player persona only, distinct mechanism from guide — content vs speaker axis (Q3/Q3-bis); per-swipe replay blob on `Swipe` for guide+impersonate retry, snapshot stays pure world-state freeze (Q4); narrator renders bare, no speaker prefix (Q5); impersonate saves as player-voiced message, retryable via blob (Q6); separate `PresetType::Impersonate` preset replacing narrator voice apparatus, persona injected into instruction (Q7/Q7b); guide/impersonate mutually exclusive per turn (Q8); guide on continue+retry not retrigger (Q9, reconciled with Q12); slash-command parser entry for all three (Q10); narrator generate-then-add via continue (Q11); guide replaces player input, runs continue path (Q12); `/guide` slash command no button (Q13); slash auto-suggestion menu (Q14).

Nine implementation tickets graduate (see `research/04-design-synthesis.md` §Implementation ticket graduation): narrator type+rendering, replay blob+storage, slash parser, guide layer, impersonate preset, narrator generate path, auto-suggestion UI, research (specs+tests), documentation.

## Scope and method

- Tree: `95ebb6ee` with a clean working tree (only ticket 07's status line changed). The full gate passed on this tree: `logs/build_20261011_124531.log`, integration `1610 passed, 0 failed, 2 skipped`, browser `27 passed, 0 failed`, guardrails 162, architecture 1. To force a trigger, the Quantifier was set to `openrouter-gpt-4o-mini` for the trigger run. The Narrator was set to `openrouter-gpt-4o-mini` for the Retrigger and event-Retry run, because `deepseek-v4-flash` spent its token budget on the first Retrigger.
- Browser: headless Chrome 154 at 1280x856, plus 1024x700 for the Game and Settings tabs.
- Exercised for real: about ten turns, the text-check preview with "Send with edits", a Narrator failure (Narrator on Ollama), an unreachable engine (server stopped, then restarted), Retry on a player entry, connection Edit/Cancel/back link, the Text Check card, preset Duplicate/Delete, World Create (failed, then valid) and Delete, new game, rename, switch, saved-game delete, a forced trigger, event delete, Retrigger (failed, then succeeded), and event Retry (twice).
- Screenshots: `tmp/p2-07/NN-*.png` (local only, `tmp/` is gitignored). Running notes: `tmp/p2-07/findings.md`.
- Epistemic tags: **[known]** = observed or measured; **[inferred]** = follows from code, not exercised.
- Cost: 31 recorded LLM calls (11 Narrator, 16 Quantifier, 4 Trigger), well under US$0.05.
- Data change: only the probe database. The Narrator, the Quantifier and Text Check were set back to `deepseek-v4-flash`, `ollama-gemma-4-e2b` and Disabled before the server stopped.

**Not covered:** history edit (`/history/:id`) as a restore path, because an edit does not restore a snapshot [inferred]; a phone viewport (out of scope since phase-1 ticket 19); a screen reader.

## New P1

| # | Finding | Evidence |
|---|---|---|
| S1 | **Event Retry always fails, and the failure rolls the game state back.** Retry on an event Message answers "The last turn failed to generate." (Details: "Retry failed: missing trigger context"). It failed after a Retrigger and again after a normal trigger turn. The retry restores the snapshot of the main narration (the anchor in `find_retry_anchor_msg`). That snapshot was written when the narration was first saved, before movement and before the trigger context existed. `save_message_and_snapshot` links a snapshot only to a Message saved for the first time, so the pre-event snapshot links to nothing. The failure path then saves the restored state as the current state: after the retry the player was back in `courtyard` (the story shows the Entrance Hall), Gabriella's `trigger_fired` was cleared, and the next turn into the hall fired the same non-repeating trigger a second time. Tier-1 scenario 10.1 passes because `seed_event_flow` links a snapshot that holds `last_trigger` to the main narration (`src/test_support/fixtures.rs:752`), which the real pipeline never does. | [known] `20`, `/debug/state` before and after, snapshot ids 63 and 67–82 in the probe DB |

## Binding prior decisions

Each item binds a new turn-state model. "Touches" says whether the source touches generations, Snapshots, retries or writers.

1. **The owner ruled the docs right and the code wrong for per-Swipe state.** Source: [`seed-evidence.md`](seed-evidence.md) §1. Binds: a Swipe's pointer must hold the state its own generation produced, including the Quantifier's updates. Touches Snapshot pointers and writers.
2. **Impersonate redo runs the full tail (quantifier → engine commit → trigger).** Source: [`../../_closed/guided-generations-architecture/issues/01-deepen-narration-turn-module.md`](../../guided-generations-architecture/issues/01-deepen-narration-turn-module.md), decision 3, and the map index. Binds: re-impersonate is not a "generate one swipe and stop" form; `swipe_new.md` I.6 needs the spec edit, not the code. Touches retries.
3. **Swipe snapshots are captured pre-tail at message-add time, so `switch_swipe` semantics are unchanged.** Source: same ticket, decision 3. Binds the closed map's own pointer model — and it **conflicts** with decision 1. The model must resolve the conflict; it may not keep both silently. Touches Snapshot pointers.
4. **One narration-generation module owns the narrate-and-persist prefix; callers resolve the inputs; no redo flag.** Source: gg01 decisions 1–2. Binds the module shape and the retry entry. Touches generations and retries.
5. **No redo-policy seam: the anchor query stays in `MessageService`, classification and reconstruction stay `pub(crate)`.** Source: gg01 decision 4. Binds where the rewind rule may live. Touches retries.
6. **The engine generates text; every Message has Swipes; a Swipe stores the inputs that produced it; a new swipe redoes the last generation.** Source: [`gg06`](../../guided-generations-architecture/issues/06-revise-branch-conceptual-model.md). Binds the vocabulary and the target rule. Touches generations, retries and the glossary.
7. **One gated dispatcher `process_action(Action)`; the entry-time impersonate preset pin.** Source: [`gg03`](../../guided-generations-architecture/issues/03-collapse-steering-entry-dispatcher.md). The dispatcher binds; the **pin is superseded** — `NarrationGeneration::resolve_preset_choice` resolves the active preset at generation time and spec 22.4 agrees. Touches generations.
8. **`PromptContext` keeps its `guide` and `impersonate` fields; no prompt-policy module.** Source: [`gg04`](../../guided-generations-architecture/issues/04-deepen-steering-prompt-policy.md). Binds the prompt seam. Touches generations (weakly).
9. **The stored-inputs attachment stays on `GameState::push_message`; no owning module.** Source: [`gg02`](../../guided-generations-architecture/issues/02-deepen-replay-steering-module.md). Binds where the Swipe gains its stored inputs. Touches writers.
10. **One commit carries the four execution pieces; the merge gates on `python build.py`.** Source: [`gg07`](../../guided-generations-architecture/issues/07-pre-merge-handoff-shape.md). A process decision. It does **not** bind the turn model.
11. **An event Retry restores the Snapshot of the Swipe it redoes; a failed redo restores the click-time state when it persisted no Swipe, and keeps the attempt's world when it did.** Source: [`p2-09`](../../dashboard-ui-review-phase2/issues/09-fix-event-retry-snapshot.md). Tested by `swipe_new.md` 10.5–10.7, 11.9, 11.10. Touches retries and Snapshots.
12. **`check_retry_anchor` validates the anchor's Snapshot on purpose (property I.7), and the event redo loads its own pointer separately.** Source: p2-09 follow-up 2. Binds the guard. Touches Snapshots.
13. **A failed trigger continuation adds no story-log Message; the anchor and the target read the same predicate.** Source: [`p2-10`](../../dashboard-ui-review-phase2/issues/10-report-failed-trigger-without-message.md). Binds the failure channel and the anchor rule. Touches generations and writers.
14. **The room name goes on the Narration that arrives in the room, and the option B question (the header must agree with the Snapshot a swipe switch restores) is deferred to this map's ticket 03.** Source: [`p2-15`](../../dashboard-ui-review-phase2/issues/15-room-name-on-arriving-narration.md), the user decision and the deferred note. Touches writers and Snapshot pointers.

## Facts this ticket could not settle

- **The conflict between the owner's per-Swipe ruling and gg01's "snapshots are captured pre-tail".** Both are prior decisions. No document says which Snapshot a Swipe must point at, or whether a second (result) pointer is needed. This is the first decision of the model.
- **Who may write game state.** No doc, spec or ADR states a writer rule. The nearest statement is `architecture.md`'s self-healing sentence, which assumes the slot owner is the only writer. The grilling tickets own this.
- **What a swipe switch must restore.** `swipe_switch.md` pins only the `Idle` status and the cleared options. It does not say which Snapshot, or that the header must agree with it (p2-15 defers that here).
- **The rewind point of a main Retry.** The docs say "the last generation"; the code rewinds per Input row. No spec covers a Retry of a continue or of a post-impersonate Narration.
- **Whether arrival narration must claim the generation slot.** No doc states a writer rule, and research 05 refutes half of seed §3 (arrival never persists `Generating`).
- **Whether `pending_location` survives.** Ticket 15 kept it as a bootstrap seed; `subplan-c` plans its deletion. The model must pick one.
- **`CONTEXT.md` has no generation entry.** The scope names one; the glossary has none. A new model that needs "generation", "rewind state" or "result state" as terms must add them.

# Map: the Rust rebuild

Labels: wayfinder:map

## Destination

A build plan for [target design](../turn-state-model/assets/target-design.md) version 2 in the current Rust crate, built in place. The plan includes every design choice that is still open (the Job shape, the edges), the test rework, and a ruling on each open `architecture-deepening` ticket. With this plan, an implementer can start with nothing left to decide.

(Redrawn 2026-10-16 by [Decide: keep Rust and build the new design in place](issues/03-decide-keep-rust-build-in-place.md). The first Destination was "keep Rust or rewrite". The folder keeps the name `platform-choice` because the turn-state-model map links to it.)

## Decisions so far

- [Research: what explicit state machines and reducers give the new design, in Rust and in other languages](issues/01-research-state-machines-and-reducers.md) — the claim is opinion with no measurement; the design already removes impossible states by derivation, so an explicit form adds detection (generated tests over the stop table) and three small gaps (G1–G3), not prevention; it does not make the language choice clearer.
- [Prototype: the Job as a pure state machine, next to a straight `generate`](issues/02-prototype-job-as-pure-state-machine.md) — both shapes sketched and measured as points of comparison, with no choice: option P doubles the code of the Job (236 against 116 lines), breaks rule 7, and keeps the stop table in a test as option S does; the busy state costs about the same in both.
- [Decide: keep Rust and build the new design in place](issues/03-decide-keep-rust-build-in-place.md) — keep Rust; the map is redrawn to end with a build plan that covers the full design, the test rework, problems A and B, and the open `architecture-deepening` tickets.
- [Decide the shape of the Job and the busy state](issues/05-decide-job-and-busy-state-shape.md) — option S for both (straight `generate`; plain `GameWriter` methods): a pure machine costs about double, breaks rule 7, and ruling R9 of the test-placement ticket refuses its unit-table gain; fork 1 is `JobPlan` plus one runner, gap G1 is a `run_step` wrapper with new rule 17, gap G2 is a `SavedText` token, and gap G3 is one generated tier-1 stop test.
- [Research: sort the open architecture-deepening tickets against the new design](issues/04-research-sort-architecture-deepening.md) — storage is the only edge that needs a new decision (tickets 10 and 11, which take AD-01, 02, 03 and the lookup of AD-16); AD-11 is settled, AD-14 is moot, and AD-06, 12, 15 and 17 are settled where the build touches them and a later effort for the rest.
- [Research: race tests for the guard and the job id check](issues/06-research-race-tests-for-guard.md) — recommends no scheduler tool: every write is one hold of one lock, so the holdable fake reaches every class of order; six interleavings at tier 1 (one is gap G3), and a proposed guardrail rule 18 (one `hold` per writer) that keeps the one-hold condition; `loom` and `shuttle` need a unit test that ruling R9 forbids and a second compile in the build slot. The owner's ruling is [Decide the race tests and guardrail rule 18](issues/12-decide-race-tests-and-rule-18.md).
- [Decide the test rule outside the designed scope](issues/08-decide-test-rule-outside-designed-scope.md) — one unit-test rule for the whole repository (a unit test only inside a seam contract); a seam contract only behind a port boundary (storage, the LLM providers, Harper, each Agent, and the `Narrator`, which takes over prompt assembly); tests that the build does not break stay on a pinned legacy list, and the owner moves them when it makes sense.
- [Research: the storage constraints that the rebuild must keep](issues/10-research-storage-constraints-for-rebuild.md) — 17 constraints for the storage seam: failure injection must move to each `Tx` record write and keep today's name-keyed API for kept methods; the in-memory backend needs a unit mechanism (a copy-and-swap is simplest); a port trait in `application/ports/` needs a changed arch-lint rule, because arch-lint 0.4.3 cannot make an exception; new types keep their inherent impls in their own file.
- [Decide the storage seam of the rebuild](issues/11-decide-storage-seam-of-rebuild.md) — keep the `Backend` enum and put the repositories on `Storage` (no trait, no port, no arch-lint change; `application → storage`); the in-memory `Tx` copies and swaps; a typed `TxWrite` key injects a failure at each record write; the CRUD services stay; one new `Storage` read finds the newest Game of a World; the entries are `transaction` and `transaction_new_game`.
- [Prototype: decide the crate split and the dev-build loop](issues/07-prototype-crate-split-and-dev-build-loop.md) — no crate split and no Cranelift; the loop's cost is the eight test binaries a targeted test never runs (8.5 s of 13.2 s), so the plan takes target selection in `build.py test-pattern` (13.2 s → 5.0-5.6 s after a one-line edit); Cranelift adds 2 s on the all-binaries shape at the noise ceiling, nothing on the targeted shapes, and is 19 % slower than the seeded, sccache-warm cold path; peak memory is ~2 GB either way.
- [Decide the build path](issues/09-decide-build-path.md) — six green preparation slices on `main` (P0 the test rule, P1 `ActiveGame`/`CurrentGame`, P2 delete the arrival opening, P3 `SwipeState` with `apply_world_rules`, P4 the Agent edge on values, P5 the storage `Tx`), then one core step on its own branch, and no follow-up slice; one implementer at a time; each guardrail rule and each doc change lands with its slice; no other work during the build; [Write the build plan](issues/14-write-the-build-plan.md) writes the plan into `docs/plans/`.
- [Decide the race tests and guardrail rule 18](issues/12-decide-race-tests-and-rule-18.md) — no scheduler tool; rule 18 (one hold per `gate.rs` function, counted through calls to other holding functions) lands in the core step; the holdable model fake lands in P4, with the rewritten 12.1 and 15.1 tests and I1's Action and `/options` cases; I3 to I6 are new scenarios in the core step, all in `tests/http/races.rs`.
- [Decide the rebuilt repository's module shape, docs and guardrails for agents](issues/13-decide-module-shape-docs-and-guardrails.md) — all 18 rules, with four table-driven syn walkers: banned name, call site, type check, call count. Today's 23 rules stay as they are. 20 are kept, 2 dead walkers are re-pointed, and 1 is retired. The rows stay in Rust, and `generate_guardrails_doc.py` parses them. A path-limited row that matches no file fails. The machinery lands in P0, and each row lands with its code. The docs model and the DOC anchor rule stay. `game_flow.md` and `storage.md` are rewritten in place. The ownership trail is a *who owns what* section in `architecture_system.md`. Only today's inherent-impl locality rule is enforced, and the stricter one-type-per-file rule is not.
- [Review: the design and the build decisions against standard engineering practice](issues/15-review-design-against-standard-practice.md) — three independent reviewers find the runtime design standard. The owner trimmed what was around it: the core step stays one step but names a short tier-1 red window, and the target tests come first. Pure `domain/model/` code may have plain unit tests, and the count pin goes. 18 rules become 14, and rule 3 becomes a capability token. Tier 1 runs on SQLite `:memory:`, so there is no copy-and-swap `Tx`. Amends tickets 08, 09, 11 and 13.
- [Decide the four gaps that the build plan found](issues/16-decide-the-build-plan-gaps.md) — option A for all four: P5 moves tier 1 to SQLite `:memory:` and gives `Tx` no production caller; the red target tests land on `main` at the end of P5 with `#[ignore]`; P4 makes the fake strict and runs the real Quantifier at tier 1; `test_support` gets the rule-3 token through a hidden `gate.rs` constructor and one call-site row. 15 rules, not 14. Amends tickets 11, 12 and 15.
- [Decide the nine gaps that the review of the build plan found](issues/17-decide-the-plan-review-gaps.md) — option A for all nine: P1 keeps the game-changed check (read through `GameCatalogue`); the rule-3 token is `TxToken` in `storage/` with a `pub(crate)` constructor and a call-site row (amends 16 Q4); `apply_game_rules` in `domain/model/utils/game_rules.rs` returns an outcome and `GameState` keeps wrappers for story side effects; `Option` fields until C6 discards saved Games; P4 builds the `HookInput` value types; the P5 `Tx` has the Game record writes and rule 9 moves to C6; mechanically broken legacy tests change in place (amends 09); no trackers yet.
- [Write the build plan](issues/14-write-the-build-plan.md) — the plan is [`docs/plans/rust-rebuild-build-plan.md`](../../docs/plans/rust-rebuild-build-plan.md), read by the owner 2026-10-17: P0 to P5 then the core step C1 to C7 (C4 the one red commit), each with content, scenarios, tests, guardrail rules, docs and a done check, gated by `/simple-after-plan` per commit; gaps settled by tickets 16 and 17 and the plan review. The Destination is reached; the next step is the build map, one `task` ticket per slice, after the owner merges `dashboard-ui-review-phase3` to `main`.

## Out of scope

- **Language and platform candidates** (TypeScript, Go, Python, SillyTavern, Marinara) — Rust stays: [Decide: keep Rust and build the new design in place](issues/03-decide-keep-rust-build-in-place.md).
- **The language part of "what an AI-native project needs"** (how well models write each language, compiler against loop speed) — no language move.
- **A black-box test oracle that runs against two servers** — there is no second server. The test rework stays in scope.
- **The parts tied to Rust** (`harper-core`, Askama, `arch-lint`, `syn`, `build.py`, the Rust skills) — they stay.
- **The edges that the build moves with no new design** (the inside of the Agents, Triggers and the game rules, prompt assembly, the HTTP views outside the design, the LLM transport) — the build moves them across the new seams with no change of logic: [research 04](assets/research-04-architecture-deepening-sort.md) §3. Storage is not in this line: tickets 10 and 11.
- **A `StorageBackend` trait** ([Deepen Storage into a StorageBackend trait](../architecture-deepening/issues/02-deepen-storage-into-backend-trait.md)) — the build keeps the `Backend` enum; a trait move of all storage is a later effort: [Decide the storage seam of the rebuild](issues/11-decide-storage-seam-of-rebuild.md) R1.
- **The rest of four `architecture-deepening` tickets**, each a later effort ([research 04](assets/research-04-architecture-deepening-sort.md) §2): [Deepen PromptAssembler](../architecture-deepening/issues/06-deepen-prompt-assembler-absorb-helpers.md) (the `token_budget.rs` constants); [Share one Agent call core](../architecture-deepening/issues/12-share-agent-call-core.md) (the shared prompt blocks and the retry loop, inside the Agent edge, under the LLM-test policy); [One fragment error policy](../architecture-deepening/issues/15-single-fragment-error-policy.md) (the handlers outside the design: the Validation conflict, `EngineError::Config` in `AppState`); [Flatten LLM transport](../architecture-deepening/issues/17-flatten-llm-transport.md) (with `prompt_merge.rs`; no file of the build).
- **A measured trial of the state-machine forms across languages** (TypeScript union with `fast-check`, XState) — no language move; the Rust forms are covered by prototype 02.

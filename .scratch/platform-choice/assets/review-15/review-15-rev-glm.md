## 1. Verdict

The design is in a sensible state overall. Its load-bearing choices are standard practice for a single-process, single-user, SQLite web app: repositories plus a unit of work, a single-writer guard with an ownership token, a request-scoped Game id, a hook registry with typed outputs, per-version state instead of copied snapshots. The real deviations cluster in three places, and none of them is required by the spec: an enforced-structure programme (the pass-ids rules and their walkers) that goes beyond what the measured defects need; a test rule that inverts the standard pyramid by banning unit tests outside seam contracts; and a one-merge core cutover on a long-lived branch. All three are workable and two of them carry their own mitigations, but the first two should be trimmed before the build plan is written, because they add standing friction that no measured defect buys back.

## 3. Parts that are standard or sensibly simpler

- **Repositories + unit of work** (ticket 11): reads by `GameId`, record writes only on a `Tx`, save units as writer methods — the standard shape. No port trait for one impl plus a test fake is the right simplification, not a deviation.
- **Single writer + ownership token**: `JobWriter` as the only write handle of a running Job, the job id check under the guard = the standard optimistic-concurrency shape for an in-process job.
- **The guard discipline**: held for one check plus one save unit, never across an LLM call — textbook.
- **Per-Swipe full state instead of Snapshot copies** (D-01/D-04): the same trade SillyTavern and Marinara make (research 13, 14); it deletes the live-record-plus-copies mechanism rather than adding one.
- **`CurrentGame` extractor + one `Refusal` → `200`/`400`/`500` mapping** — standard axum practice.
- **One `generate` + `JobPlan` as data + one runner** (ticket 05 item 1): the standard command/plan pattern; replaces five ordering functions plus arrival. Net code goes down (~3,577 out, ~1,845 + ~80 hooks in).
- **Hook registry with one trait and one typed output per hook** (sketch 24): the standard plugin pattern, with a real stated requirement (the owner's multi-agent quote, sketch 24 §0) and a prior art precedent (Marinara).
- **`SavedText` capability token** (ticket 05 item 3): standard Rust typestate; a compiler proof where other designs use review.
- **Property tests for the pure game rules**; tail-derived values instead of stored derived fields.
- **Sequencing**: the 240-call-site mechanical break first (P1); each guardrail lands with the code it guards; docs rewritten in place rather than split (ticket 13 §4); a *who owns what* section instead of a rotting module→decision map.
- **Dead-path assertion for walkers** (ticket 13 §2): fixes a real, confirmed rot (the two dead walkers in `layers.rs`).
- **No throw-away `GameState`↔`SwipeState` adapter** in P3: `SwipeState` inside `GameState` means the 330 world-rule lines move once, not twice.

## 4. Top three changes before the build plan is written

1. **Trim the pass-ids rules to what the defects prove.** Keep rule 7's field half (no record fields on `Job` — the stale-copy proof) and rule 8 (one LLM call per function). Drop the parameter half of rule 7, and demote rules 17 and 18's indirect counting to review-only. This removes the two most bespoke walker rows while keeping every measured defect class covered.
2. **Let pure functions have plain unit tests.** Amend ticket 08 R2: a pure function (`Tail`, `SwipeState`, `GenerationOrder`, `apply_game_rules`, the derived dock/status rules) may have ordinary unit tests; seam contracts stay for the ports; tier-1 stays the behaviour net. This restores the standard pyramid for the layer where unit tests are cheapest and most precise, without reopening the legacy-list freeze.
3. **De-risk the core cutover.** Either split the core merge into two green merges (records + `Tx` + `GameWriter`/`JobWriter` with the old save methods kept one slice longer; then pipeline, views, deletions), or keep the one-merge branch but write the stop matrix and the five race scenarios before the branch opens, and cap its lifetime. The temporary dual surface it avoids is a few hundred lines of old methods — cheap insurance against one large red-window merge.

# Split tests/helpers by concern

## Summary

`tests/helpers/fixtures.rs` and `tests/helpers/pipeline_helpers.rs` each mix two concepts: pure data builders (free fns) and extension traits on foreign types (`impl ... for Storage`, `impl ... for DefaultApplicationService`). Splitting by concept so each file answers one question ("where do I get test data?" vs "where do test-only behavior extensions live?" vs "where's the polling helper?"). No behavior change. No production-code touch.

## Key Changes

New file layout under `chronicler_engine/tests/helpers/`:

| File | Contents |
|---|---|
| `fixtures.rs` | Pure data builders only: existing `create_test_*` fns + `create_minimal_test_state` (moved from `pipeline_helpers.rs`) |
| `storage_ext.rs` (new) | `trait TestWorldFixture for Storage` + impl |
| `application_ext.rs` (new) | `trait PipelineHelpers for DefaultApplicationService` + impl + private `player_name` helper |
| `sqlite_test_app_builder.rs` | Unchanged |

`wait_for_condition` moves to the existing `tests/test_utils/wait.rs`, which already houses sibling polling helpers (`wait_for_llm_idle`, `wait_for_status_ready`, `wait_for_element_children`). No new `sync.rs` file — polling helpers belong with polling helpers, and `wait.rs` is already re-exported across all test binaries via `#[path = "../test_utils/mod.rs"] mod test_utils;`.

No trait renames. `TestWorldFixture` and `PipelineHelpers` keep current names (rename is out of scope; behavior change for importers).

Module declarations updated in two test binary roots that `#[path = "../helpers/..."]` these modules:

- `tests/integration/mod.rs`
- `tests/infrastructure/invariant_contract.rs`

Both also already import `test_utils`; `wait_for_condition` becomes accessible via `test_utils::wait_for_condition` wherever `wait_for_condition` was previously reachable.

Import path updates across ~10 test files:

- `use crate::pipeline_helpers::PipelineHelpers` → `use crate::application_ext::PipelineHelpers`
- `use crate::fixtures::TestWorldFixture` → `use crate::storage_ext::TestWorldFixture`
- `pipeline_helpers::wait_for_condition` → `test_utils::wait_for_condition`
- `use crate::pipeline_helpers::create_minimal_test_state` → `use crate::fixtures::create_minimal_test_state`
- `use crate::pipeline_helpers::{create_minimal_test_state}` → same as above

`tests/AGENTS.md` STRUCTURE block regenerated by `build.py` (AUTO-STRUCTURE-TESTS markers). One-line descriptions for the two new `_ext` files added; `pipeline_helpers.rs` entry removed.

## Assumptions

- Pure-refactor: no semantic change to any function, trait, or impl body.
- Extension traits stay as extension traits (wired-app-restructure ticket 11 already locked this decision; not re-litigated here).
- Trait names stay as-is (`TestWorldFixture`, `PipelineHelpers`); only file names follow the `<type>_ext.rs` Rust idiom. Renaming traits is out of scope because it changes every importer's `use` path and blurs the refactor's intent.
- `player_name` private helper stays with `PipelineHelpers` because only `add_input_and_save` uses it.
- `wait_for_condition` moves to `test_utils/wait.rs` alongside its sibling polling helpers. Both test binaries (`integration/`, `infrastructure/`) already declare `mod test_utils;` via `#[path]`, so the function is reachable without new module declarations.
- `build.py`'s `AUTO-STRUCTURE-TESTS` marker rewrites the STRUCTURE block on next run; one-line descriptions for new files edited manually if the auto-summary is stale.

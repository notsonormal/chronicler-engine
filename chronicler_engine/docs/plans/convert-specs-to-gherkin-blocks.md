# Convert Feature Specs to Gherkin Code Blocks

## Summary

Replace the `**Given** / **When** / **Then** / **And**` markdown-step
convention in `chronicler_engine/docs/specs/*.md` with fenced
```` ```gherkin ```` code blocks. Strip the `**` keyword markers, the
two-trailing-space hard line breaks, and backticks around code spans
inside the blocks. Drop the now-meaningless format check from
`validate_feature_spec.py` (coverage + orphan checks remain). Refresh
the auto-generated `AGENTS.md` structure index.

Locked decisions (from plan-mode questions):

- **Backticks inside gherkin blocks: STRIP.** They render as literal
  characters inside a fence; monospace + quotes already convey
  code/string. Matches the "cleaner" goal.
- **Validator format check: DROP.** Coverage + orphan checks stay;
  format check gone. Fenced blocks are robust by construction.

## Key Changes

- `chronicler_engine/docs/specs/{actions,swipe_new,retrigger,browser,story_log,reset}.md`
  — each `#### Scenario X.Y: Title` heading followed by a
  ```` ```gherkin ```` block holding the steps.
- `chronicler_engine/scripts/validate_feature_spec.py` — remove
  `KEYWORD_LINE_RE`, `check_spec_format`, the format-violation summary
  term, and the format-violation report block. Rewrite the docstring's
  first line as a complete one-line summary (so the
  `AGENTS.md` structure index regenerates cleanly).
- `chronicler_engine/AGENTS.md` — line 157 bullet regenerated by
  `generate_structure_index.py` from the new docstring first line.

Unchanged (in scope of this plan, explicitly):

- `#### Scenario X.Y: Title` markdown headings — stay (validator's
  `SCENARIO_RE` still parses them).
- `// [spec-path] SCENARIO: X.Y` test annotations in
  `tests/http/*.rs` and `tests/browser/behaviour.rs` — stay.
- `## Invariants` sections at the bottom of specs — stay as markdown
  prose (their `**I.1**` bullets are not GWT steps).
- `validate_feature_spec.py` coverage + orphan logic
  (`SCENARIO_RE`, `SCENARIO_COMMENT_RE`, `TEST_ATTR_RE`,
  `parse_spec_scenarios`, `parse_test_annotations`) — unchanged.

### Phase 2: Convert specs (8 SP)

Per-file transformation rules (apply identically to each scenario):

1. After the `#### Scenario X.Y: Title` line and one blank line, open
   ` ```gherkin `.
2. For each step line: strip the `**` around `Given`/`When`/`Then`/`And`
   (e.g. `**Given**` → `Given`); strip the trailing two-space hard line
   break; strip backticks around code spans
   (`` `message_service.load_messages()` `` → `message_service.load_messages()`).
3. Keep sub-bullets (e.g. `  - one Input entry whose text is "look"`)
   as indented `- ` lines inside the block; strip backticks inside them
   too.
4. Close the block with ` ``` ` on its own line after the last step.
5. One blank line before the next heading or `---`.

## Assumptions

- `gherkin` language hint renders acceptably in the user's viewer
  (Obsidian + GitHub). Obsidian falls back to plain monospace if no
  gherkin grammar is installed — still readable, just uncolored.
- `#### Scenario X.Y: Title` headings stay as markdown (not converted
  to gherkin `Scenario:` keyword inside the block). Validator's
  `SCENARIO_RE` is unchanged.
- `// [spec-path] SCENARIO: X.Y` test annotations in
  `tests/http/*.rs` and `tests/browser/behaviour.rs` are unchanged.
- `## Invariants` sections stay as markdown prose; their `**I.1**`
  bullets and any backticks in invariant prose are not touched.
- Backticks are stripped only inside the new gherkin fences; backticks
  elsewhere in the specs (invariant prose, top intro paragraphs) stay.
- Sub-bullets under a step keep their `  - ` prefix inside the fence
  (render as literal indented dashes; read as bullets in monospace).
- Historical plan docs
  (`docs/plans/ticket-8-*.md`, `pilot-feature-spec-*.md`, etc.)
  mention the old "2 trailing spaces / hard line break" rule — they
  are records and are not edited.
